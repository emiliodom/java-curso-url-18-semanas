Persistencia con JPA: todo en una página

Ejemplos con la Biblioteca Comunitaria Semilla (entidad Libro).

La idea central

Hasta la Semana 11 los datos vivían en una List dentro del servicio: al apagar la app, se perdían. Hoy los guardas en una base de datos con tres piezas:

PiezaQué esAnalogía
Entidad (Libro)Clase Java anotada que se convierte en tablaEl molde de la ficha de catálogo
Repositorio (LibroRepository)Interfaz que Spring implementa por tiEl bibliotecario que archiva y busca fichas
ORM / HibernateTraduce objetos Java a filas SQL y de vueltaUn traductor Java ↔ SQL

Anotaciones e imports (dos familias en la misma clase)

Persistencia (jakarta.persistence) dice cómo se guarda; validación (jakarta.validation.constraints) dice qué se acepta.

Anotación / tipoImport completoQué haceError si falta
@Entityjakarta.persistence.EntityLa clase es una tablacannot find symbol; sin tabla
@Idjakarta.persistence.IdLlave primariaNo identifier specified for entity
@GeneratedValuejakarta.persistence.GeneratedValueId automáticocannot find symbol
GenerationTypejakarta.persistence.GenerationTypeIDENTITY: numeración de la basecannot find symbol
@Columnjakarta.persistence.ColumnAjusta una columna (largo, nullable)cannot find symbol
JpaRepositoryorg.springframework.data.jpa.repository.JpaRepositoryMétodos listos: save, findAll, findById, deleteById, countcannot find symbol (falta data-jpa)
@NotBlank, @Size, @Min, @Max, @NotNulljakarta.validation.constraints.*Reglas del formulario (Semana 11)cannot find symbol; es jakarta, no javax

Lo que ya trae JpaRepository<Libro, Long>

MétodoQué haceDevuelve
save(libro)insert si el id es nulo; update si el id existeel libro guardado
findAll()Todas las filasList<Libro>
findById(id)Una fila por id (puede no existir)Optional<Libro>
deleteById(id)Borra la filanada
count()Cuántas filas haylong

Nombre del método derivado: find + By + Campo + Containing + IgnoreCase. El campo debe existir en la entidad.

Piezas mínimas de la entidad

package gt.edu.url.tallerjpa.model;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class Libro {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String titulo;
    private String autor;
    private Integer anioPublicacion;
    private boolean disponible = true;

    public Libro() {
    }

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getTitulo() {
        return titulo;
    }

    public void setTitulo(String titulo) {
        this.titulo = titulo;
    }

    public String getAutor() {
        return autor;
    }

    public void setAutor(String autor) {
        this.autor = autor;
    }

    public Integer getAnioPublicacion() {
        return anioPublicacion;
    }

    public void setAnioPublicacion(Integer anioPublicacion) {
        this.anioPublicacion = anioPublicacion;
    }

    public boolean isDisponible() {
        return disponible;
    }

    public void setDisponible(boolean disponible) {
        this.disponible = disponible;
    }
}
  • Clase → tabla: Libro → libro; anioPublicacion → anio_publicacion.
  • Siempre un constructor vacío.
  • Campos numéricos de formulario: Integer, no int.

Optional en una línea

Libro libro = libroRepository.findById(id)
        .orElseThrow(() -> new IllegalArgumentException("No existe un libro con id " + id));

Es una cajita que puede venir vacía: si hay libro lo da, si no, lanza tu error con tu mensaje.

La promesa de la Semana 14
Hoy trabajas contra H2 en tu computadora; en la Semana 14 la misma aplicación se conecta a Neon (PostgreSQL en la nube) sin cambiar una sola línea de Java: solo cambia el archivo de configuración del perfil. Render hospeda la aplicación, pero su base de datos gratuita expira, por eso la base vive en Neon.

Los tres archivos de configuración

1. application.properties (elige el perfil)

# Ruta: src/main/resources/application.properties
# Aquí van solo las cosas que valen para TODOS los perfiles.
spring.application.name=taller-jpa

# Perfil activo. "dev" = tu computadora. En la Semana 14 el hosting lo cambiará a "prod".
spring.profiles.active=dev

2. application-dev.properties (hoy)

# Ruta: src/main/resources/application-dev.properties
# Perfil "dev": H2 EN ARCHIVO, en tu computadora.

# jdbc:h2:file:  = base de datos guardada en un archivo (sobrevive al reinicio)
# ./datos/biblioteca = carpeta "datos" dentro de tu proyecto, archivo "biblioteca"
spring.datasource.url=jdbc:h2:file:./datos/biblioteca
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

# update = crea la tabla si no existe y CONSERVA los datos. (create y create-drop los borran.)
spring.jpa.hibernate.ddl-auto=update

# Muestra en la terminal el SQL que Hibernate escribe por ti.
spring.jpa.show-sql=true

# Consola web de H2: http://localhost:8080/h2-console
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

3. application-prod.properties (Semana 14)

# Ruta: src/main/resources/application-prod.properties
# Perfil "prod": PostgreSQL en Neon. HOY NO SE USA; queda preparado para la Semana 14.
# Los ${...} son "huecos" que se llenan con variables de entorno del hosting (Render).
# Así tu contraseña real nunca se escribe en el código ni se sube a GitHub.
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=org.postgresql.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=false

# La consola de H2 NO debe existir en producción.
spring.h2.console.enabled=false

Render fijará SPRING_PROFILES_ACTIVE=prod, con lo que Spring ignora dev y carga prod. Las contraseñas viven en las variables de entorno de Render, nunca en GitHub.

Por qué tu entidad no cambia

Las anotaciones JPA describen la tabla de forma genérica; Hibernate la traduce al SQL de cada base. Por eso la Guía 12 tiene un doble criterio: (1) funciona con H2 local y (2) la entidad y el repositorio no necesitan cambios para reconectar a PostgreSQL. Si Libro tuviera SQL escrito a mano para H2, ese segundo punto se rompería.
