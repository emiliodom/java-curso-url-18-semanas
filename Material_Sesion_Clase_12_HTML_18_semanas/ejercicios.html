Paso 3 — Añade persistencia a Jugador Modifica el archivo existente Id y constructor vacío obligatorios

No crees un segundo Jugador.java ni borres el que ya validaste. En src/main/java/gt/edu/url/tallerformularios/model/Jugador.java, conserva campos, getters/setters y anotaciones Bean Validation. package gt.edu.url.tallerformularios.model;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

@Entity
public class Jugador {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "El nombre es obligatorio.")
    @Size(min = 3, max = 40, message = "El nombre debe tener entre 3 y 40 caracteres.")
    @Column(nullable = false, length = 40)
    private String nombre;

    @NotNull(message = "La edad es obligatoria.")
    @Min(value = 5, message = "La edad mínima para inscribirse es 5 años.")
    @Max(value = 17, message = "Esta categoría admite hasta 17 años.")
    @Column(nullable = false)
    private Integer edad;

    @NotBlank(message = "Selecciona una posición.")
    @Column(nullable = false)
    private String posicion;

    @NotBlank(message = "El correo del encargado es obligatorio.")
    @Email(message = "Escribe un correo válido, por ejemplo: nombre@correo.com")
    @Column(nullable = false)
    private String correoEncargado;

    @NotBlank(message = "El teléfono es obligatorio.")
    @Pattern(regexp = "[0-9]{8}", message = "El teléfono debe tener exactamente 8 dígitos.")
    @Column(nullable = false, length = 8)
    private String telefono;

    public Jugador() {
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getNombre() { return nombre; }
    public void setNombre(String nombre) { this.nombre = nombre; }
    public Integer getEdad() { return edad; }
    public void setEdad(Integer edad) { this.edad = edad; }
    public String getPosicion() { return posicion; }
    public void setPosicion(String posicion) { this.posicion = posicion; }
    public String getCorreoEncargado() { return correoEncargado; }
    public void setCorreoEncargado(String correoEncargado) { this.correoEncargado = correoEncargado; }
    public String getTelefono() { return telefono; }
    public void setTelefono(String telefono) { this.telefono = telefono; }
}

Los getters/setters que ya tienes se conservan; agrega los de id. Integer permite que una edad vacía llegue como null y la rechace @NotNull. Persistencia (jakarta.persistence) y validación (jakarta.validation.constraints) conviven en los mismos campos.

✅ Checkpoint: Jugador conserva las cinco validaciones, tiene @Entity, @Id, id Long y constructor vacío.

package gt.edu.url.tallerformularios.service;

import java.util.List;

import org.springframework.stereotype.Service;

import gt.edu.url.tallerformularios.model.Jugador;
import gt.edu.url.tallerformularios.repository.JugadorRepository;

@Service
public class JugadorService {

    private final JugadorRepository jugadorRepository;

    public JugadorService(JugadorRepository jugadorRepository) {
        this.jugadorRepository = jugadorRepository;
    }

    public void guardar(Jugador jugador) {
        jugadorRepository.save(jugador);
    }

    public List<Jugador> listarTodos() {
        return jugadorRepository.findAll();
    }

    public Jugador buscarPorId(Long id) {
        return jugadorRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException(
                        "No existe un jugador con id " + id));
    }

    public void eliminar(Long id) {
        jugadorRepository.deleteById(id);
    }

    public long contar() {
        return jugadorRepository.count();
    }
}
El controlador todavía puede llamar a guardar y listarTodos. La diferencia es que ya no existe una lista: el servicio delega en JugadorRepository.

Kit para iniciar el módulo completo de Jugador desde cero
Para quien todavía no construyó el módulo de Semana 11. Empieza en Spring Initializr, genera el proyecto con las dependencias seleccionadas en la página y después crea cada carpeta y archivo indicado abajo.

1. Genera el proyecto en Spring Initializr

  1. Abre start.spring.io. Elige Project Maven, Language Java, Packaging Jar y la versión estable de Spring Boot que usa el proyecto funcional de Semana 12 (4.1.1, sin SNAPSHOT ni RC).
  2. Completa los nombres: Group gt.edu.url, Artifact taller-formularios, Name taller-formularios, Package name gt.edu.url.tallerformularios y Java 17 (o la misma versión que ya instalaste).
  3. En Add Dependencies, busca y agrega desde la página: Spring Web, Thymeleaf, Validation, Spring Data JPA, H2 Database, Spring Boot DevTools y PostgreSQL Driver.
  4. Genera, descomprime y abre la carpeta taller-formularios en VS Code. Acepta la importación Maven. No pegues ni agregues dependencias manualmente en pom.xml: Initializr las incorpora al proyecto generado.
El paquete se revisa a mano antes de generar
Initializr puede proponer gt.edu.url.taller-formularios al derivarlo del Artifact. Borra el guion en el campo Package name y confirma que quede exactamente gt.edu.url.tallerformularios. El Artifact y la carpeta conservan el guion; el paquete Java no.
Sí usamos Spring Boot DevTools durante el desarrollo
Selecciona esa dependencia en Initializr para que los cambios en clases Java provoquen la recarga automática mientras trabajas. No se reinicia al registrar o editar un jugador; al cambiar una plantilla HTML basta refrescar el navegador. La prueba de persistencia de abajo se hace con un apagado completo y un arranque manual para comprobarla deliberadamente, sin depender de la recarga de DevTools.
Nota sobre la consola H2 en Spring Boot 4
La lista actual de Spring Initializr no ofrece H2 Console como dependencia seleccionable. Para mantener este Kit completamente generable desde la web, no activamos /h2-console; comprueba el guardado desde la lista de la aplicación y la persistencia después de detenerla por completo y volver a iniciarla manualmente. La consola del proyecto de referencia taller-jpa se configura aparte y no es necesaria para que CRUD/JPA funcione.

import jakarta.persistence.Column;

No es un error del material: son tres nombres distintos que Initializr deriva de lo que escribiste, y los tres son correctos a la vez. Solución

insert o update: save() mira el id. Si es nulo (formulario nuevo, el campo escondido va vacío) hace insert; si trae un número que ya existe (formulario de edición), hace update. Un solo método para dos trabajos.

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // Anotaciones de VALIDACIÓN (jakarta.validation, Semana 11) ...
    @NotBlank(message = "El título es obligatorio.")
    @Size(max = 120, message = "El título no puede pasar de 120 caracteres.")
    // ... y anotación de PERSISTENCIA (jakarta.persistence, hoy) sobre el mismo campo.
    @Column(nullable = false, length = 120)
    private String titulo;

    @NotBlank(message = "El autor es obligatorio.")
    @Size(min = 3, max = 80, message = "El autor debe tener entre 3 y 80 caracteres.")
    @Column(nullable = false, length = 80)
    private String autor;

    // Integer (con mayúscula), como aprendimos en la Semana 11.
    @NotNull(message = "El año de publicación es obligatorio.")

    @Max(value = 2100, message = "El año no puede pasar de 2100.")
    @Column(name = "anio_publicacion")
    private Integer anioPublicacion;

    private boolean disponible = true;

    public Libro() {
    }

        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

        return titulo;
    }

        this.titulo = titulo;

package gt.edu.url.tallerjpa.controller;

import java.util.List;

import jakarta.validation.Valid;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ModelAttribute;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

import gt.edu.url.tallerjpa.model.Libro;
import gt.edu.url.tallerjpa.service.LibroService;

@Controller
public class LibroController {

    private final LibroService libroService;

    public LibroController(LibroService libroService) {
        this.libroService = libroService;
    }

    @GetMapping("/")
    public String inicio() {
        return "redirect:/libros";
    }

    // LISTAR (y buscar, si llega ?buscar=texto)
    @GetMapping("/libros")
    public String listar(@RequestParam(required = false) String buscar, Model model) {
        List<Libro> libros;
        if (buscar == null || buscar.isBlank()) {
            libros = libroService.listarTodos();
        } else {
            libros = libroService.buscarPorTitulo(buscar);
        }
        model.addAttribute("libros", libros);
        model.addAttribute("total", libroService.contar());
        model.addAttribute("buscar", buscar);
        return "lista";
    }

    // LISTAR solo los disponibles (usa el método derivado findByDisponibleTrue)
    @GetMapping("/libros/disponibles")
    public String listarDisponibles(Model model) {
        model.addAttribute("libros", libroService.listarDisponibles());
        model.addAttribute("total", libroService.contar());
        model.addAttribute("buscar", "");
        return "lista";
    }

    // CREAR - paso 1: mostrar el formulario vacío
    @GetMapping("/libros/nuevo")
    public String nuevo(Model model) {
        model.addAttribute("libro", new Libro());
        return "formulario";
    }

    // EDITAR - paso 1: mostrar el formulario ya lleno con el libro de ese id
    @GetMapping("/libros/{id}/editar")
    public String editar(@PathVariable Long id, Model model) {
        model.addAttribute("libro", libroService.buscarPorId(id));
        return "formulario";
    }

    // CREAR y EDITAR - paso 2: guardar. Si el libro trae id, save() lo actualiza; si no, lo crea.
    @PostMapping("/libros")
    public String guardar(@Valid @ModelAttribute Libro libro, BindingResult resultado) {
        if (resultado.hasErrors()) {
            return "formulario";          // con errores: se devuelve la plantilla (Semana 11)
        }
        libroService.guardar(libro);
        return "redirect:/libros";        // sin errores: guardar -> redirigir -> mostrar (Semana 10)
    }

    // BORRAR: por POST, nunca por un enlace normal (un enlace se puede abrir sin querer)
    @PostMapping("/libros/{id}/eliminar")
    public String eliminar(@PathVariable Long id) {
        libroService.eliminar(id);
        return "redirect:/libros";
    }
}

Errores explicados y reproducibles — siempre uno a la vez

Antes de provocar un error
Usa una copia desechable del proyecto; nunca pruebes los casos 7 y 8 con la única copia de una base de datos que quieras conservar. Si usas el proyecto real, respalda primero datos/biblioteca.mv.db. No subas a GitHub una versión rota. Cambia una sola cosa, observa el mensaje, deshaz el cambio y confirma que vuelve a arrancar antes de seguir. Para errores de Maven, sincroniza el proyecto después de editar pom.xml.
Error y cómo provocarloQué observarArreglo y comprobación
1. Entidad sin llave primaria
En Libro.java, comenta temporalmente @Id y @GeneratedValue(...).		 La aplicación no arranca. Busca No identifier specified for entity en el último Caused by:. Restaura ambas anotaciones sobre Long id. Arranca otra vez y comprueba que /libros carga.
2. Falta el constructor vacío
En Libro.java, reemplaza el constructor sin parámetros por uno con parámetros, por ejemplo public Libro(String titulo) { this.titulo = titulo; }.		 Hibernate no puede crear la entidad al leer filas. Puede aparecer No default constructor for entity o un mensaje equivalente de instanciación; el punto de fallo varía por versión. Vuelve a agregar public Libro() { } y conserva también los demás constructores que necesites. Prueba listar y registrar un libro.
3. Falta JPA
Comenta temporalmente spring-boot-starter-data-jpa en pom.xml y recarga Maven.		 Los imports jakarta.persistence.* y JpaRepository quedan sin resolver: package jakarta.persistence does not exist / cannot find symbol. No es un error de la entidad: falta la dependencia. Restaura el starter, sincroniza Maven y espera a que desaparezcan los errores de compilación.
4. Falta el driver H2
Comenta solo la dependencia com.h2database:h2 en pom.xml; recarga Maven y arranca.		 El código compila, pero la aplicación no puede conectarse: busca Failed to load driver class org.h2.Driver o Failed to determine a suitable driver class. Restaura H2 con <scope>runtime</scope>, sincroniza Maven y confirma que el servidor inicia.
5. Método derivado apunta a un campo inexistente
En el repositorio, cambia findByDisponibleTrue() temporalmente por findByDisponibilidadTrue() y ajusta la llamada en el servicio.		 Spring valida el nombre al iniciar y falla con No property 'disponibilidad' found for type 'Libro'. El campo real se llama disponible. Restaura el método findByDisponibleTrue() en repositorio y servicio; vuelve a arrancar.
6. Se devuelve Optional donde se espera Libro
En LibroService.buscarPorId, intenta return libroRepository.findById(id);.		 El compilador avisa que Optional<Libro> no se puede convertir a Libro. Restaura .orElseThrow(() -> new IllegalArgumentException(...)). Así se decide explícitamente qué hacer cuando no existe ese id.
7. Datos que desaparecen con H2 en memoria
Cambia solo la URL a jdbc:h2:mem:biblioteca, registra un libro y reinicia manualmente.		 La aplicación arranca sin error; la tabla queda vacía porque la base existía solo en RAM. Es un comportamiento esperado, no un fallo de JPA. Restaura jdbc:h2:file:./datos/biblioteca, reinicia y confirma que el registro persiste.
8. Tabla vacía aunque H2 usa archivo
Cambia temporalmente ddl-auto=update por ddl-auto=create, agrega un registro y reinicia.		 La conexión al archivo funciona, pero Hibernate vuelve a crear la tabla y borra sus filas. Restaura ddl-auto=update. Con create/create-drop los datos se destruyen al inicializar o cerrar.
9. Consola H2 con 404
Desactiva temporalmente spring.h2.console.enabled o, en Spring Boot 4, comenta spring-boot-h2console.		 /h2-console devuelve 404 aunque el resto de la app pueda funcionar. Restaura el starter de consola de Boot 4 y spring.h2.console.enabled=true en application-dev.properties; reinicia porque los cambios de configuración no se recargan solos.
10. Dos procesos abren la misma base
Deja una instancia en ejecución e intenta arrancar otra desde una terminal distinta.		 H2 puede indicar Database may be already in use. Detén la instancia duplicada con Ctrl+C en su terminal y deja solo una aplicación usando el archivo.
11. Las validaciones no se aplican
En una copia desechable, quita spring-boot-starter-validation, sincroniza Maven y prueba guardar el formulario.		 Según lo que aporte el classpath, los imports jakarta.validation quedan sin resolver o las reglas dejan de ejecutarse. No confundas la anotación @Column(nullable = false) con la validación del formulario. Restaura spring-boot-starter-validation y sincroniza Maven. Confirma que el formulario vuelve a mostrar errores de @NotBlank/@NotNull.
12. Controlador fuera del paquete base
En una copia desechable, mueve LibroController a un paquete hermano que no cuelgue de gt.edu.url.tallerjpa y actualiza el package y sus imports.		 El código puede compilar y la aplicación arrancar, pero Spring no descubre el controlador y /libros responde 404. Devuelve el controlador a gt.edu.url.tallerjpa.controller (debajo del paquete de TallerJpaApplication). Reinicia y vuelve a probar la ruta.
Regla para leer errores largos
Primero identifica si es de compilación (VS Code/Maven) o de ejecución (terminal). En una traza larga busca el último Caused by:; después relaciona el mensaje con el archivo y la línea que acabas de cambiar. Si no aparece Started TallerJpaApplication, no sigas al próximo caso: restaura y arregla el actual.
