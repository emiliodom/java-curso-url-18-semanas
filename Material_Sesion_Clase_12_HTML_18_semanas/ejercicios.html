Cómo está armada esta escalera
Todo se resuelve en tu terminal y VS Code reales: no hay simuladores. Las tres preguntas ancla de esta semana
Cuando algo no funcione, revisa en este orden: (1) ¿están en el pom.xml las dependencias nuevas, spring-boot-starter-data-jpa y h2 (y spring-boot-devtools para la recarga automática)? (2) ¿la entidad tiene @Entity, @Id y un constructor vacío? (3) ¿la URL dice jdbc:h2:file: (archivo) y no jdbc:h2:mem: (memoria)?

Ejercicio 1 — Genera el proyecto y arráncalo Nivel 1

Objetivo: crear taller-jpa con las seis dependencias y comprobar que arranca. Es un proyecto de práctica desechable: tu proyecto real se toca en la página Proyecto.

Pasos

  1. Entra a start.spring.io (Spring Initializr, como en la Semana 7).
  2. Elige: Project Maven · Language Java · Spring Boot la versión estable más reciente 3.x (sin la palabra SNAPSHOT) · Group gt.edu.url · Artifact taller-jpa · Packaging Jar · Java 17 (o 21, el mismo que instalaste).
  3. Pulsa ADD DEPENDENCIES y agrega seis: Spring Web, Thymeleaf, Validation, Spring Data JPA, H2 Database y Spring Boot DevTools (esta última hace que la aplicación se recargue sola; se explica en el recuadro "Antes de seguir" más abajo).
  4. Pulsa GENERATE, descomprime el .zip y abre la carpeta taller-jpa en VS Code (File → Open Folder).
  5. Abre pom.xml y localiza las tres dependencias nuevas de hoy: spring-boot-starter-data-jpa, h2 y spring-boot-devtools.
  6. Arranca: en la terminal de VS Code (Terminal → New Terminal) escribe ./mvnw spring-boot:run (en Windows PowerShell: .\mvnw spring-boot:run). También sirve el botón ▶ Run sobre TallerJpaApplication.java.

Tu turno: lee el log. Busca la línea que dice Hibernate ORM core version y la que dice HikariPool-1 - Start completed. ¿Qué te dicen sobre lo que Spring hizo solo, sin que escribieras nada?

✅ Checkpoint: la terminal termina con Started TallerJpaApplication in ... seconds y no hay líneas rojas de error.
💡 Pista
Si el puerto 8080 está ocupado (Semana 7), cierra la otra aplicación con Ctrl+C en su terminal. Si Maven tarda minutos, es la primera descarga: espera.
Solución
Spring detectó dos cosas en el pom.xml: JPA/Hibernate y una base de datos H2. Sin que le dijeras nada más, creó una base de datos H2 temporal y conectó Hibernate a ella (por eso aparecen las líneas de Hibernate y Hikari, que es el "administrador de conexiones"). Todavía no tienes ninguna entidad, así que no hay tablas.
DependenciaQué aporta
spring-boot-starter-data-jpaJPA (las anotaciones jakarta.persistence), Hibernate (el traductor) y Spring Data (los repositorios)
h2La base de datos y su driver (el "conector" para hablarle). Solo vive en tu computadora
spring-boot-devtoolsRecarga automática en desarrollo: no tienes que parar y arrancar a mano por cada cambio (ver el recuadro "Antes de seguir")

🔁 Antes de seguir: que la aplicación se recargue sola

Hoy harás muchos cambios y los probarás. Sin ayuda, cada uno exige parar la aplicación y volver a arrancarla. Spring Boot DevTools (la sexta dependencia del Ejercicio 1) lo evita: vigila tu proyecto y se recarga cuando algo cambia. Se recarga a tres velocidades:

Qué cambiasQué pasaQué haces tú
Plantillas Thymeleaf (templates/), CSS o HTML de static/DevTools desactiva la caché de Thymeleaf; no hay reinicioSolo refrescar el navegador (F5)
Código Java (.java)Reinicio automático y rápido (1 a 2 segundos; reinicia tu código, no las librerías)Guardar y esperar (ver la condición abajo)
pom.xml y application*.propertiesNo se recargan solosDetener (Ctrl+C) y arrancar a mano. Hoy editarás varios properties: recuérdalo
Ojo con la condición: lo que dispara el reinicio es la recompilación, no el guardado. En VS Code con la extensión de Java, compilar al guardar viene activado, así que normalmente basta con guardar. Si guardas y no pasa nada, arranca la aplicación con el botón ▶ Run (o con el Spring Boot Dashboard) en lugar de una terminal externa. DevTools se desactiva solo cuando la aplicación corre empaquetada como jar en producción, así que no estorba en el despliegue de la Semana 14 (Render y Neon).

Prueba de 30 segundos

  1. Con la aplicación corriendo, abre una página de tu proyecto (si todavía no tienes ninguna, haz esta prueba al terminar el Ejercicio 4).
  2. Abre una plantilla de src/main/resources/templates/, cambia un texto visible del título y guarda.
  3. Refresca el navegador. El texto debe haber cambiado sin que reiniciaras nada.
✅ Checkpoint: viste el cambio en el navegador sin detener la aplicación. Si no ocurre, revisa que spring-boot-devtools esté en el pom.xml y que hayas guardado el archivo.

Ejercicio 2 — Tu primera entidad: una clase que se vuelve tabla Nivel 1

Objetivo: escribir Libro como @Entity y ver la tabla que Hibernate crea, usando la consola de H2.

Pasos

  1. Crea la carpeta (paquete) model dentro de src/main/java/gt/edu/url/tallerjpa/ y dentro el archivo Libro.java con este contenido (es una versión mínima; la completa está en el Kit, archivo 6): 
    package gt.edu.url.tallerjpa.model;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

@Entity
public class Libro {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String titulo;
    private String autor;
    private Integer anioPublicacion;
    private boolean disponible = true;

    public Libro() {
    }

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getTitulo() {
        return titulo;
    }

    public void setTitulo(String titulo) {
        this.titulo = titulo;
    }

    public String getAutor() {
        return autor;
    }

    public void setAutor(String autor) {
        this.autor = autor;
    }

    public Integer getAnioPublicacion() {
        return anioPublicacion;
    }

    public void setAnioPublicacion(Integer anioPublicacion) {
        this.anioPublicacion = anioPublicacion;
    }

    public boolean isDisponible() {
        return disponible;
    }

    public void setDisponible(boolean disponible) {
        this.disponible = disponible;
    }
}
  2. Reemplaza todo el contenido de src/main/resources/application.properties por esto (H2 en memoria, por ahora): 
    # Ruta: src/main/resources/application.properties   (versión del Ejercicio 2: H2 EN MEMORIA)
spring.application.name=taller-jpa

# jdbc:h2:mem: = base de datos que vive en la memoria RAM mientras la aplicación está encendida
spring.datasource.url=jdbc:h2:mem:biblioteca
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
  3. Arranca la aplicación y busca en la terminal una línea parecida a create table libro (...): es el SQL que Hibernate escribió por ti.
  4. Abre http://localhost:8080/h2-console. En JDBC URL escribe jdbc:h2:mem:biblioteca, usuario sa, contraseña vacía, y pulsa Connect.
  5. En el panel izquierdo aparece la tabla LIBRO. Haz clic sobre ella, y luego ejecuta SELECT * FROM LIBRO; con el botón Run.

Tu turno: ¿Con qué nombre aparece la columna del año de publicación? ¿Quién decidió ese nombre, tú o Hibernate?

✅ Checkpoint: ves la tabla LIBRO con sus cinco columnas en la consola de H2, vacía (0 filas).
💡 Pista
Si la consola dice Database not found, la JDBC URL no coincide con la del archivo application.properties: debe ser idéntica. Si da 404 en /h2-console, falta spring.h2.console.enabled=true.
Solución
La columna se llama ANIO_PUBLICACION. Lo decidió Hibernate: toma el nombre del campo Java (anioPublicacion, en camelCase) y lo convierte a minúsculas con guion bajo (anio_publicacion); H2 lo muestra en mayúsculas. La clase Libro se volvió la tabla libro. Esa es la convención nombre-de-clase → nombre-de-tabla: no tuviste que escribir ningún CREATE TABLE. La columna ID es numérica y se llena sola gracias a @GeneratedValue(strategy = GenerationType.IDENTITY).

Ejercicio 3 — El repositorio: una interfaz que funciona sola Nivel 2

Objetivo: crear LibroRepository (una interfaz) y LibroService, y ver que Spring escribe la implementación por ti.

Pasos

  1. Crea la carpeta repository junto a model y dentro LibroRepository.java: 
    package gt.edu.url.tallerjpa.repository;

import org.springframework.data.jpa.repository.JpaRepository;

import gt.edu.url.tallerjpa.model.Libro;

public interface LibroRepository extends JpaRepository<Libro, Long> {
}
  2. Crea la carpeta service y copia LibroService.java completo del Kit (archivo 8). Verás subrayados rojos en findByTituloContainingIgnoreCase y findByDisponibleTrue: es normal, aún no existen en el repositorio.
  3. Para quitar los rojos, agrega esas dos líneas dentro de las llaves de LibroRepository, y el import java.util.List; arriba (el archivo completo está en el Kit, archivo 7): 
    List<Libro> findByTituloContainingIgnoreCase(String texto);
List<Libro> findByDisponibleTrue();
  4. Arranca y busca en el log la frase Found 1 JPA repository interface.

Tu turno: abre LibroRepository.java. ¿Cuántos métodos con cuerpo escribiste tú? ¿Y dónde está entonces el código que guarda en la base de datos?

✅ Checkpoint: la aplicación arranca y el log dice Found 1 JPA repository interface.
💡 Pista
Piensa en un restaurante: tú entregas al mesero una carta (la interfaz) y la cocina (Spring) se encarga de prepararla. No existe ninguna clase LibroRepositoryImpl escrita por ti.
Solución
No escribiste ninguna línea de código que guarde. Al arrancar, Spring Data lee tu interfaz, ve que extiende JpaRepository<Libro, Long> y genera en memoria una clase que la implementa, con save(), findAll(), findById(), deleteById() y count() ya funcionando. Por eso en el log aparece "Found 1 JPA repository interface": encontró tu repositorio y le fabricó la implementación. Los dos métodos extra los entiende por su nombre (ver Ejercicio 6).

Ejercicio 4 — Crear y listar… y el reinicio que lo borra todo Nivel 2

Objetivo: completar el flujo formulario → controlador → servicio → repositorio → base de datos, y vivir en carne propia el problema de la base en memoria.

Pasos

  1. Reemplaza Libro.java por la versión completa del Kit (archivo 6): suma las reglas de validación de la Semana 11 sobre los mismos campos.
  2. Copia del Kit: LibroController.java (archivo 9) en la carpeta controller; formulario.html y lista.html (archivos 10 y 11) en src/main/resources/templates/; y estilos.css (archivo 12) en src/main/resources/static/.
  3. Arranca y entra a http://localhost:8080. Pulsa + Registrar un libro y guarda tres libros (por ejemplo, "Rebeca Lazo", "Don Quijote", "El Principito").
  4. En la terminal busca las líneas insert into libro ...: es el SQL que Hibernate escribió cada vez que pulsaste Guardar.
  5. En http://localhost:8080/h2-console (misma URL jdbc:h2:mem:biblioteca) ejecuta SELECT * FROM LIBRO;. Deben aparecer tus tres filas.
  6. La prueba incómoda: detén la aplicación tú mismo (Ctrl+C en la terminal) y vuelve a arrancarla a mano. Actualiza la lista del navegador.
¿Por qué manual? Con DevTools, el reinicio automático de DevTools también vacía la base en memoria, pero aquí queremos que lo hagas tú, a propósito, para que veas que la prueba es tuya y no un efecto secundario. Ojo: con DevTools cualquier cambio en un archivo Java que provoque reinicio también vacía la base en memoria; lo notarás cada vez que corrijas código, y eso hace el problema más molesto. Esa molestia es justo lo que resuelve el Ejercicio 8.

Tu turno: después del reinicio, ¿cuántos libros hay? ¿Entonces la base de datos sirvió de algo todavía? Anota tu respuesta: la resuelve el Ejercicio 8.

✅ Checkpoint: viste tres libros en la tabla LIBRO (consola de H2) y viste que, tras el reinicio, la lista volvió a estar vacía.
💡 Pista
Fíjate en la primera parte de la JDBC URL: jdbc:h2:mem:biblioteca. ¿Qué crees que significa mem?
Solución
Después del reinicio hay cero libros. Es exactamente la promesa incumplida: jdbc:h2:mem: significa "base de datos en la memoria RAM", y la RAM se vacía al apagar la aplicación. Pasaste de una List en memoria a… una base de datos en memoria: mejor organizada, pero igual de olvidadiza. Lo que falta es decirle a H2 que guarde en un archivo del disco. Eso es el Ejercicio 8.

Ejercicio 5 — Editar, borrar y el misterio de Optional Nivel 3

Objetivo: completar el CRUD (actualizar y borrar) y entender por qué findById() no devuelve un Libro a secas.

Pasos

  1. Registra un libro y pulsa Editar. Cambia el título y Guarda. Observa en la terminal que ahora aparece update libro set ... (y no un insert), y que en la lista no se duplicó el libro.
  2. Pulsa Eliminar en un libro. Busca en la terminal delete from libro where id=?.
  3. Escribe en el navegador http://localhost:8080/libros/999/editar (un id que no existe). Lee el mensaje del error.
  4. Provoca el error de tipos. En LibroService.java, dentro de buscarPorId, comenta el return y escribe esta línea temporal: 
    Libro libro = libroRepository.findById(id);
    VS Code la marcará en rojo. Pasa el cursor sobre el error y léelo. Luego deshaz el cambio (Ctrl+Z) para volver a orElseThrow.

Tu turno: ¿cómo supo save() si debía hacer insert o update? (Mira el campo escondido id en formulario.html.)

✅ Checkpoint: editar cambia la fila en lugar de duplicarla, borrar la elimina, y viste el mensaje incompatible types: Optional<Libro> cannot be converted to Libro.
💡 Pista
Imagina que alguien te pide "tráeme el libro 999" y ese libro no existe. ¿Qué entregas: un libro vacío, o una cajita que puede traer un libro o venir vacía?
Solución

insert o update: save() mira el id. Si es nulo (formulario nuevo, el campo escondido va vacío) hace insert; si trae un número que ya existe (formulario de edición), hace update. Un solo método para dos trabajos.

Optional: findById() devuelve Optional<Libro>: una "cajita" que puede contener un libro o puede venir vacía, porque ese id podría no existir. Java te obliga a decidir qué hacer en ese caso, en lugar de explotar más tarde con un error confuso. orElseThrow(...) significa: "si hay libro, dámelo; si la caja está vacía, lanza este error con mi mensaje". Por eso /libros/999/editar muestra un error con el texto No existe un libro con id 999.

Borrar por POST: el botón Eliminar es un formulario POST, no un enlace. Un enlace puede abrirse sin querer (un buscador, una vista previa) y borrar datos.

Ejercicio 6 — Métodos derivados: Spring entiende el nombre Nivel 3

Objetivo: usar la búsqueda por título y el filtro de disponibles, y comprobar que Spring convierte el nombre del método en una consulta.

Pasos

  1. En la lista, escribe parte de un título (con mayúsculas o minúsculas distintas) en Buscar por título y pulsa Buscar.
  2. Quita la marca Disponible a un libro (Editar) y luego pulsa el enlace Solo disponibles.
  3. En la terminal compara el SQL de ambas búsquedas: busca like y where ... disponible=?.
  4. Provoca el error de nombre. En LibroRepository.java, cambia temporalmente findByDisponibleTrue por findByDisponibilidadTrue (y el mismo cambio en LibroService.java). Arranca y lee el error. Luego regresa al nombre correcto.

Tu turno: descompón el nombre findByTituloContainingIgnoreCase en cuatro palabras y di qué significa cada una.

✅ Checkpoint: la búsqueda ignora mayúsculas, el filtro muestra solo los disponibles, y viste un error que dice No property 'disponibilidad' found for type 'Libro'.
💡 Pista
Spring lee el nombre de izquierda a derecha: find (buscar) By (por) Titulo (el campo) Containing (que contenga) IgnoreCase (sin distinguir mayúsculas).
Solución
find + By + Titulo + Containing + IgnoreCase = "busca por el campo titulo los que contengan el texto, sin importar mayúsculas". findByDisponibleTrue = "busca los que tengan disponible verdadero". Al arrancar, Spring comprueba que cada palabra del nombre sea un campo real de la entidad. Con Disponibilidad no existe tal campo, y la aplicación ni siquiera arranca: el error aparece al inicio, no cuando alguien hace clic. Eso es una ventaja: los errores de nombre se descubren de inmediato. Regla práctica: el nombre del campo en el método debe ser idéntico (en camelCase, con mayúscula inicial) al campo de la clase.

Ejercicio 7 — Provoca los errores del mapeo (y aprende a leerlos) Nivel 3

Objetivo: romper a propósito la entidad de tres maneras, leer cada mensaje y arreglarlo. Estos errores dan mensajes largos y poco claros: mejor conocerlos hoy, con calma.

Pasos

  1. Haz una prueba a la vez. Después de cada una, restaura el archivo y comprueba que arranca antes de pasar a la siguiente.
  2. Prueba A — sin @Id. En Libro.java comenta las líneas @Id y @GeneratedValue(...). Arranca. Lee el final de la terminal.
  3. Prueba B — sin constructor vacío. Borra public Libro() { } y agrega en su lugar un constructor con parámetros: 
    // Dentro de Libro.java, Java ya no regala el constructor vacío:
public Libro(String titulo, String autor) {
    this.titulo = titulo;
    this.autor = autor;
}
// (y el "public Libro() { }" del Kit está borrado)
    Arranca, entra a /libros y registra un libro. Lee el mensaje.
  4. Prueba C — sin el driver de H2. En pom.xml comenta el bloque <dependency> de com.h2database y recarga Maven (VS Code pregunta "Sync"; acepta). Arranca y lee el error.

Tu turno: en cada prueba, encuentra la última línea que empieza con Caused by:. Casi siempre ahí está la causa real; lo de arriba es solo ruido de Spring.

✅ Checkpoint: las tres pruebas están restauradas y la aplicación vuelve a mostrar Started TallerJpaApplication.
💡 Pista
Los mensajes son largos. No los leas de arriba hacia abajo: ve al final y busca el último Caused by:.
Solución
PruebaMensaje clave (en el último Caused by)Qué significa
A. Sin @IdNo identifier specified for entity: gt.edu.url.tallerjpa.model.LibroToda entidad necesita una columna que identifique cada fila. La aplicación no arranca.
B. Sin constructor vacíoNo default constructor for entity 'gt.edu.url.tallerjpa.model.Libro'Hibernate crea un Libro vacío por cada fila que lee y luego rellena los campos. Sin constructor sin parámetros no puede. Según la versión falla al arrancar o en el primer findAll()/findById().
C. Sin driver H2Failed to load driver class org.h2.Driver (o Failed to determine a suitable driver class)Hibernate existe pero no tiene el "conector" para hablar con H2. Falla al arrancar la conexión.

¿Por qué B es tan traicionero? En cuanto escribes cualquier constructor con parámetros, Java deja de regalarte el constructor vacío. Si todavía lo necesitas, tienes que escribirlo tú.

Prueba extra (solo leer, no la hagas): si quitaras spring-boot-starter-data-jpa, ni siquiera compilaría: los import jakarta.persistence.* quedarían en rojo con package jakarta.persistence does not exist.

Ejercicio 8 — El reinicio que no borra nada: H2 en archivo y perfiles Nivel 4

Objetivo: cumplir por fin la promesa: guardar en un archivo, separar la configuración en perfiles y comprobar que los datos sobreviven al reinicio.

Pasos

  1. Crea tres archivos en src/main/resources/ con el contenido del Kit: application.properties (archivo 2, reemplaza el que tenías), application-dev.properties (archivo 3) y application-prod.properties (archivo 4).
  2. Fíjate en la diferencia clave entre la versión anterior y la nueva: jdbc:h2:mem:biblioteca pasó a jdbc:h2:file:./datos/biblioteca.
  3. En el archivo .gitignore de tu proyecto, al final, agrega una línea nueva: datos/ (la base de datos local no se sube a GitHub).
  4. Arranca. En el log busca The following 1 profile is active: "dev". En el explorador de VS Code debe aparecer la carpeta datos/ con un archivo biblioteca.mv.db.
  5. Registra tres libros. Detén la aplicación tú mismo (Ctrl+C) y vuelve a arrancarla a mano. Hazlo así a propósito: el reinicio automático de DevTools también vacía la base en memoria, pero aquí queremos que lo hagas tú, a propósito, para que veas que la prueba es tuya y no un efecto secundario. Además, los cambios en application*.properties nunca se recargan solos.
  6. Abre la lista. Entra a la consola de H2 con la nueva URL jdbc:h2:file:./datos/biblioteca y ejecuta SELECT * FROM LIBRO;.
  7. Lee application-prod.properties sin usarlo: observa los tres huecos ${DB_URL}, ${DB_USER} y ${DB_PASSWORD}.

Tu turno: ¿qué aparece en tu lista después del reinicio? Y responde con tus palabras: ¿por qué el archivo application-prod.properties usa ${...} en lugar de escribir la contraseña directamente?

✅ Checkpoint: tus tres libros siguen ahí después de apagar y encender la aplicación. 🎉 Es el momento por el que esperaste desde la Semana 8.
💡 Pista
Si aparece Database may be already in use, hay otra copia de la aplicación corriendo: cierra todas las terminales de Maven y vuelve a intentar (con DevTools, si arrancas dos veces la misma aplicación, este error es más fácil de provocar). Si tus datos se borran aunque uses file, revisa que diga ddl-auto=update y no create ni create-drop.
Solución
Los libros siguen ahí porque H2 ahora escribe en el archivo datos/biblioteca.mv.db de tu disco, que no se borra al apagar la aplicación. ddl-auto=update significa "crea la tabla si no existe, pero no toques los datos". Con create la tabla se reconstruiría vacía en cada arranque.

Los perfiles: application.properties contiene lo común y elige el perfil con spring.profiles.active=dev. Spring carga entonces application-dev.properties encima. En la Semana 14 el hosting activará prod (con una variable de entorno) y Spring cargará application-prod.properties: la misma aplicación, otra base de datos.

Los ${...}: son huecos que se llenan con variables de entorno del servidor. Así la contraseña de Neon vive solo en Render, nunca en tu código ni en GitHub, donde cualquiera podría leerla. Y como Libro.java, LibroRepository.java y el resto no mencionan ninguna base de datos concreta, no habrá que tocarlos.

package gt.edu.url.tallerjpa.model;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;

// @Entity: "esta clase es una tabla". Por convención la tabla se llamará "libro".
@Entity
public class Libro {

    // @Id: la columna que identifica cada fila (la llave primaria). OBLIGATORIA.
    // IDENTITY: la base de datos numera sola (1, 2, 3...). Funciona igual en H2 y en PostgreSQL.
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // Anotaciones de VALIDACIÓN (jakarta.validation, Semana 11) ...
    @NotBlank(message = "El título es obligatorio.")
    @Size(max = 120, message = "El título no puede pasar de 120 caracteres.")
    // ... y anotación de PERSISTENCIA (jakarta.persistence, hoy) sobre el mismo campo.
    @Column(nullable = false, length = 120)
    private String titulo;

    @NotBlank(message = "El autor es obligatorio.")
    @Size(min = 3, max = 80, message = "El autor debe tener entre 3 y 80 caracteres.")
    @Column(nullable = false, length = 80)
    private String autor;

    // Integer (con mayúscula), como aprendimos en la Semana 11.
    @NotNull(message = "El año de publicación es obligatorio.")
    @Min(value = 1000, message = "El año debe ser 1000 o posterior.")
    @Max(value = 2100, message = "El año no puede pasar de 2100.")
    @Column(name = "anio_publicacion")
    private Integer anioPublicacion;

    private boolean disponible = true;

    // CONSTRUCTOR VACÍO: Hibernate lo necesita para crear un Libro por cada fila que lee.
    public Libro() {
    }

    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getTitulo() {
        return titulo;
    }

    public void setTitulo(String titulo) {
        this.titulo = titulo;
    }

    public String getAutor() {
        return autor;
    }

    public void setAutor(String autor) {
        this.autor = autor;
    }

    public Integer getAnioPublicacion() {
        return anioPublicacion;
    }

    public void setAnioPublicacion(Integer anioPublicacion) {
        this.anioPublicacion = anioPublicacion;
    }

    public boolean isDisponible() {
        return disponible;
    }

    public void setDisponible(boolean disponible) {
        this.disponible = disponible;
    }
}
Dos familias de anotaciones sobre la misma clase
jakarta.persistence.* (JPA, de hoy: @Entity, @Id, @GeneratedValue, @Column) describen cómo se guarda el dato. jakarta.validation.constraints.* (Semana 11: @NotBlank, @Size, @Min, @Max, @NotNull) describen qué datos se aceptan. No se estorban: cada una responde una pregunta distinta. Ojo: @Column(nullable = false) es una regla de la base de datos; @NotBlank es una regla del formulario.

import java.util.List;

import gt.edu.url.tallerjpa.model.Libro;
import gt.edu.url.tallerjpa.repository.LibroRepository;

@Service
public class LibroService {

    // Ya NO hay una List en memoria: el repositorio guarda en la base de datos.
    private final LibroRepository libroRepository;

    // Inyección por constructor (igual que en la Semana 10, pero ahora recibe el repositorio).
    public LibroService(LibroRepository libroRepository) {
        this.libroRepository = libroRepository;
    }

    public List<Libro> listarTodos() {
        return libroRepository.findAll();
    }

    public List<Libro> buscarPorTitulo(String texto) {
        return libroRepository.findByTituloContainingIgnoreCase(texto);
    }

    public List<Libro> listarDisponibles() {
        return libroRepository.findByDisponibleTrue();
    }

    // findById devuelve Optional<Libro> ("puede haber un libro o puede no haber nada").
    // orElseThrow: si hay libro, lo entrega; si no, lanza este error.
    public Libro buscarPorId(Long id) {
        return libroRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("No existe un libro con id " + id));
    }

    // save() sirve para CREAR (id nulo) y para ACTUALIZAR (id ya existente).
    public Libro guardar(Libro libro) {
        return libroRepository.save(libro);
    }

    public void eliminar(Long id) {
        libroRepository.deleteById(id);
    }

    public long contar() {
        return libroRepository.count();
    }
}

package gt.edu.url.tallerjpa.controller;

import java.util.List;

import jakarta.validation.Valid;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.ModelAttribute;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;

import gt.edu.url.tallerjpa.model.Libro;
import gt.edu.url.tallerjpa.service.LibroService;

@Controller
public class LibroController {

    private final LibroService libroService;

    public LibroController(LibroService libroService) {
        this.libroService = libroService;
    }

    @GetMapping("/")
    public String inicio() {
        return "redirect:/libros";
    }

    // LISTAR (y buscar, si llega ?buscar=texto)
    @GetMapping("/libros")
    public String listar(@RequestParam(required = false) String buscar, Model model) {
        List<Libro> libros;
        if (buscar == null || buscar.isBlank()) {
            libros = libroService.listarTodos();
        } else {
            libros = libroService.buscarPorTitulo(buscar);
        }
        model.addAttribute("libros", libros);
        model.addAttribute("total", libroService.contar());
        model.addAttribute("buscar", buscar);
        return "lista";
    }

    // LISTAR solo los disponibles (usa el método derivado findByDisponibleTrue)
    @GetMapping("/libros/disponibles")
    public String listarDisponibles(Model model) {
        model.addAttribute("libros", libroService.listarDisponibles());
        model.addAttribute("total", libroService.contar());
        model.addAttribute("buscar", "");
        return "lista";
    }

    // CREAR - paso 1: mostrar el formulario vacío
    @GetMapping("/libros/nuevo")
    public String nuevo(Model model) {
        model.addAttribute("libro", new Libro());
        return "formulario";
    }

    // EDITAR - paso 1: mostrar el formulario ya lleno con el libro de ese id
    @GetMapping("/libros/{id}/editar")
    public String editar(@PathVariable Long id, Model model) {
        model.addAttribute("libro", libroService.buscarPorId(id));
        return "formulario";
    }

    // CREAR y EDITAR - paso 2: guardar. Si el libro trae id, save() lo actualiza; si no, lo crea.
    @PostMapping("/libros")
    public String guardar(@Valid @ModelAttribute Libro libro, BindingResult resultado) {
        if (resultado.hasErrors()) {
            return "formulario";          // con errores: se devuelve la plantilla (Semana 11)
        }
        libroService.guardar(libro);
        return "redirect:/libros";        // sin errores: guardar -> redirigir -> mostrar (Semana 10)
    }

    // BORRAR: por POST, nunca por un enlace normal (un enlace se puede abrir sin querer)
    @PostMapping("/libros/{id}/eliminar")
    public String eliminar(@PathVariable Long id) {
        libroService.eliminar(id);
        return "redirect:/libros";
    }
}
