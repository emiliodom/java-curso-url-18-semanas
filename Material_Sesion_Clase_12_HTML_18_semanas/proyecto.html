Tus datos, por fin guardados de verdad

Primero la guía paso a paso para persistir los datos de tu proyecto real con JPA, y al final la plantilla calificable. Fecha límite: antes de la Sesión 13.
Antes de empezar
Necesitas tu módulo de la Semana 11: taller-formularios, formulario validado de Jugador y almacenamiento en una lista. Esta guía continúa esa misma aplicación: no cambies de entidad ni vuelvas a empezar. Si te falta un archivo, usa la pestaña de continuación Jugador del Kit. taller-jpa aparece allí solo como referencia funcional separada.
Si tu módulo de Semana 11 ya está completo, úsalo como base.
Esta guía no pide rehacer el formulario ni sus validaciones: indica qué se conserva y qué se añade para que el mismo Jugador se guarde con JPA.
Conservar de Semana 11 Agregar en Semana 12 Modificar para JPA Imprescindible: revisa el error si falta
Revisa estos requisitos antes de buscar un error más complejo
  • Sin spring-boot-starter-data-jpa: imports JPA sin resolver o JpaRepository no encontrado.
  • Sin el driver H2: la aplicación no arranca (Failed to load driver class org.h2.Driver).
  • Sin @Entity: la clase no queda mapeada (Not a managed type); sin @Id: No identifier specified for entity. Sin constructor vacío, Hibernate no puede crear la entidad.
  • Sin el repositorio dentro del paquete escaneado: Spring no lo registra y falla la inyección del servicio. Si un método derivado usa un campo inexistente, el arranque falla con No property ... found for type.
  • Sin H2 Console habilitada (y su starter en Boot 4): /h2-console responde 404; esto no significa que JPA no haya guardado.
  • Sin el campo oculto id al editar: se crea otra fila. Con ddl-auto=create o una URL mem: los datos desaparecen al reiniciar.
  • El driver PostgreSQL solo es necesario al activar prod; si ese perfil declara org.postgresql.Driver y falta la dependencia, falla la conexión.
Dos criterios para esta guía
Esta guía se califica con un doble criterio: (1) tu proyecto funciona contra H2 local y los datos sobreviven al reinicio; (2) tu entidad y tu repositorio no necesitan cambios de código para reconectarse a PostgreSQL en la Semana 14 (solo cambiará el archivo de configuración del perfil, hacia Neon).

Parte guiada — persiste tu proyecto real

Paso 1 — Agrega las dependencias que falten Nuevas en Semana 12 JPA y H2 son obligatorias

En el pom.xml existente, agrega Spring Data JPA, H2 Database, Spring Boot DevTools y, si usas Spring Boot 4, H2 Console. No dupliques nada que ya figure en tu POM ni borres web, Thymeleaf o Validation de Semana 11. Incluye PostgreSQL si configuras ya el perfil prod.

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <scope>runtime</scope>
    <optional>true</optional>
</dependency>

<!-- Spring Boot 4: habilita /h2-console. -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-h2console</artifactId>
</dependency>

<!-- Inclúyelo si application-prod.properties declara org.postgresql.Driver. -->
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
DevTools (opcional pero recomendada): recarga la aplicación sola cuando se recompila código y, al refrescar, permite ver cambios de plantilla sin reiniciar. No recarga cambios en pom.xml ni en application*.properties: para esos, Ctrl+C y arranca a mano. Se desactiva sola en producción.
En Spring Boot 4 la consola H2 tiene su propio starter, spring-boot-h2console. El proyecto de referencia también incluye desde ahora el driver PostgreSQL porque su perfil prod ya declara org.postgresql.Driver; esto no conecta a Neon mientras el perfil activo sea dev. En versiones anteriores, revisa los nombres de starter que generó Initializr en vez de reemplazar tu pom.xml.
Si falta una, el error es distinto
Sin data-jpa, los imports de jakarta.persistence salen en rojo (no compila). Sin h2, compila pero al arrancar dice Failed to load driver class org.h2.Driver. Recarga Maven después de editar.
✅ Checkpoint: el proyecto arranca (o falla solo por falta de configuración, lo que se arregla en el Paso 5).

Paso 2 — Añade persistencia a tu entidad Modifica el archivo existente Id y constructor vacío obligatorios

Tomas el Jugador que ya validaste en la Semana 11 y le sumas persistencia sin quitar ninguna regla. Conserva el paquete base real de tu aplicación — en la continuación de clase es gt.edu.url.tallerformularios — y coloca las capas debajo de él.

Los dos grupos de anotaciones conviven
jakarta.persistence describe cómo se guarda; jakarta.validation.constraints conserva las reglas de la Semana 11. Agrega @Entity, id y constructor vacío. Mantén Integer para edad, no uses int.
// src/main/java/gt/edu/url/tallerformularios/model/Jugador.java
package gt.edu.url.tallerformularios.model;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

@Entity
public class Jugador {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "El nombre es obligatorio.")
    @Size(min = 3, max = 40, message = "El nombre debe tener entre 3 y 40 caracteres.")
    @Column(nullable = false, length = 40)
    private String nombre;

    @NotNull(message = "La edad es obligatoria.")
    @Min(value = 5, message = "La edad mínima para inscribirse es 5 años.")
    @Max(value = 17, message = "Esta categoría admite hasta 17 años.")
    private Integer edad;

    @NotBlank(message = "Selecciona una posición.")
    @Column(nullable = false)
    private String posicion;

    @NotBlank(message = "El correo del encargado es obligatorio.")
    @Email(message = "Escribe un correo válido.")
    @Column(nullable = false)
    private String correoEncargado;

    @NotBlank(message = "El teléfono es obligatorio.")
    @Pattern(regexp = "[0-9]{8}", message = "El teléfono debe tener exactamente 8 dígitos.")
    @Column(nullable = false, length = 8)
    private String telefono;

    public Jugador() { }   // obligatorio para JPA

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getNombre() { return nombre; }
    public void setNombre(String nombre) { this.nombre = nombre; }
    public Integer getEdad() { return edad; }
    public void setEdad(Integer edad) { this.edad = edad; }
    public String getPosicion() { return posicion; }
    public void setPosicion(String posicion) { this.posicion = posicion; }
    public String getCorreoEncargado() { return correoEncargado; }
    public void setCorreoEncargado(String correoEncargado) { this.correoEncargado = correoEncargado; }
    public String getTelefono() { return telefono; }
    public void setTelefono(String telefono) { this.telefono = telefono; }
}
  • El código conserva las reglas de validación del formulario de Semana 11 y agrega un Long id autogenerado.
  • public Jugador() { }: constructor vacío que JPA necesita.
  • Integer edad permite distinguir la casilla vacía de la edad cero.
✅ Checkpoint: tu clase tiene @Entity, @Id y constructor vacío, y todos los import están sin subrayado rojo.

Paso 4 — Cambia el almacenamiento de tu servicio Edita el servicio de S11

En la Semana 10 el servicio guardaba en una List en memoria. Ahora delega en el repositorio. Observa que findById usa orElseThrow:

// src/main/java/gt/edu/url/tallerformularios/service/JugadorService.java
package gt.edu.url.tallerformularios.service;

import java.util.List;
import org.springframework.stereotype.Service;
import gt.edu.url.tallerformularios.model.Jugador;
import gt.edu.url.tallerformularios.repository.JugadorRepository;

@Service
public class JugadorService {

    private final JugadorRepository repositorio;

    public JugadorService(JugadorRepository repositorio) {
        this.repositorio = repositorio;
    }

    public List<Jugador> listarTodos() {
        return repositorio.findAll();
    }

    public Jugador buscarPorId(Long id) {
        return repositorio.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("No existe un registro con id " + id));
    }

    public Jugador guardar(Jugador jugador) {
        return repositorio.save(jugador);
    }

    public void eliminar(Long id) {
        repositorio.deleteById(id);
    }
}

Tu controlador casi no cambia: sigue llamando a guardar, listarTodos, etc. Para editar necesitarás un campo escondido id en el formulario (th:field="*{id}") y para borrar un formulario con POST: el Kit de Ejercicios trae ambos.

✅ Checkpoint: ya no queda ningún ArrayList en tu servicio.

Paso 5 — Configura H2 en archivo con perfiles Configuración nueva URL y ddl-auto determinan la persistencia

Tres archivos en src/main/resources/. Seguimos con la aplicación taller-formularios y usamos la base jugadores:

# Ruta: src/main/resources/application.properties
# Aquí van solo las cosas que valen para TODOS los perfiles.
spring.application.name=taller-formularios

# Perfil activo. "dev" = tu computadora. En la Semana 14 el hosting lo cambiará a "prod".
spring.profiles.active=dev
# Ruta: src/main/resources/application-dev.properties
# Perfil "dev": H2 EN ARCHIVO, en tu computadora.

# jdbc:h2:file:  = base de datos guardada en un archivo (sobrevive al reinicio)
# ./datos/jugadores = carpeta "datos" dentro de tu proyecto, archivo "jugadores"
spring.datasource.url=jdbc:h2:file:./datos/jugadores
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

# update = crea la tabla si no existe y CONSERVA los datos. (create y create-drop los borran.)
spring.jpa.hibernate.ddl-auto=update

# Muestra en la terminal el SQL que Hibernate escribe por ti.
spring.jpa.show-sql=true

# Consola web de H2: http://localhost:8080/h2-console
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

# Las plantillas Thymeleaf se actualizan al refrescar el navegador.
spring.thymeleaf.cache=false
# Ruta: src/main/resources/application-prod.properties
# Perfil "prod": PostgreSQL en Neon. HOY NO SE USA; queda preparado para la Semana 14.
# Los ${...} son "huecos" que se llenan con variables de entorno del hosting (Render).
# Así tu contraseña real nunca se escribe en el código ni se sube a GitHub.
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=org.postgresql.Driver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=false

# La consola de H2 NO debe existir en producción.
spring.h2.console.enabled=false

Y en tu .gitignore agrega al final una línea:

datos/
Por qué application-prod.properties si hoy no se usa: hoy trabajas contra H2 en tu computadora; en la Semana 14 la misma aplicación se conectará a Neon (PostgreSQL en la nube) sin cambiar una sola línea de Java: solo cambia el archivo de configuración del perfil. Render hospedará la aplicación y Neon la base, porque la base gratuita de Render expira. No actives prod hoy.
✅ Checkpoint: al arrancar, el log dice The following 1 profile is active: "dev" y aparece la carpeta datos/.

Paso 6 — Prueba el CRUD y el reinicio Comprueba lo nuevo

  1. Crear: registra 3 registros reales de tu institución.
  2. Listar: comprueba que salen.
  3. Editar: cambia uno; verifica que NO se duplica.
  4. Eliminar: borra uno.
  5. Consola: abre /h2-console con la URL jdbc:h2:file:./datos/tu-nombre (usuario sa, sin contraseña) y haz un SELECT * sobre tu tabla.
  6. Reinicio: detén la aplicación, arráncala de nuevo y comprueba que tus datos siguen ahí.
  7. Id inexistente: visita /tu-ruta/999/editar y observa el mensaje.
✅ Checkpoint: tus registros sobreviven al reinicio. Esta es la prueba más importante de la guía.
