Sección especial · Cómo agregar páginas

Páginas estáticas (/creditos) y páginas con parámetros

Agregar una página no es una «característica nueva»: reutiliza la misma receta (plantilla + método de controlador + regla de seguridad). Todo el código de esta página se probó en la copia «Biblioteca» del Kit. Los ejemplos usan Libro; sustitúyelo por tu entidad.

🧭 Tres formas de tener una página

TipoEjemplo¿Necesita Java?Cuándo usarla
A. Archivo estáticostatic/creditos.html → se abre en /creditos.htmlNoTexto fijo sin menús ni datos. La URL lleva .html.
B. Plantilla sin datos ⭐templates/creditos.html + @GetMapping("/creditos") → /creditosUn método de 3 líneasPáginas «de contenido» con URL limpia (créditos, ayuda, acerca de). La recomendada.
C. Plantilla con parámetros/libros/7 · /buscar?genero=NovelaUn método que recibe el parámetroCuando el contenido depende de qué registro o qué filtro pide el visitante.

📄 Parte 1 · La página /creditos en 4 pasos

1
VS Code Crea la plantilla src/main/resources/templates/creditos.html
<!doctype html>
<html lang="es" xmlns:th="http://www.thymeleaf.org">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Créditos</title>
  <link rel="stylesheet" th:href="@{/estilos.css}">
</head>
<body>
<main>
  <h1>Biblioteca Comunitaria</h1>
  <h2>Créditos</h2>
  <p>Proyecto desarrollado en el curso Programación I, Universidad Rafael Landívar.</p>
  <ul>
    <li>Autor: Tu Nombre</li>
    <li>Tecnologías: Java, Spring Boot, Thymeleaf, PostgreSQL (Neon) y Render.</li>
  </ul>
  <p><a th:href="@{/libros}">Volver a la lista</a></p>
</main>
</body>
</html>
Es una copia de error.html con otro contenido: reutilizas la misma estructura y el mismo estilos.css.
2
VS Code Agrega un método a un controlador (puedes crear PaginasController)
@Controller
public class PaginasController {

    @GetMapping("/creditos")
    public String creditos() {
        return "creditos";     // busca templates/creditos.html
    }
}
El texto que devuelve el método es el nombre del archivo sin .html. La URL (/creditos) y el nombre del archivo pueden ser distintos.
3
VS Code Decide quién puede verla en SecurityConfig
.requestMatchers("/login", "/estilos.css", "/error", "/creditos").permitAll()
Sin esta línea, anyRequest().authenticated() manda a todo visitante al login. Con ella, la página es pública. Recuerda: gana la primera regla que coincide, así que va antes de anyRequest(). Si prefieres que solo la vean usuarios con sesión, no agregues nada.
4
Navegador Enlázala y pruébala
<a th:href="@{/creditos}">Créditos</a>     <!-- en lista.html o login.html -->
Siempre th:href="@{/…}" y no href="/creditos": Thymeleaf ajusta la ruta si algún día la aplicación vive en una subcarpeta. Prueba en http://localhost:8080/creditos sin haber iniciado sesión.
Variante A: archivo en static/ (sin Java)

Coloca creditos.html en src/main/resources/static/. Spring lo sirve en /creditos.html (con la extensión; /creditos daría 404). Como SecurityConfig protege todo, agrega "/creditos.html" a la lista permitAll(). No puede usar th:* ni insertar datos: es HTML puro.

🔗 Parte 2 · Páginas que reciben parámetros

Hay dos lugares donde viaja un dato en la dirección. Mira la anatomía de una URL:

@PathVariable@RequestParam
Se ve así/libros/7/buscar?genero=Novela
En el controlador@GetMapping("/libros/{id}") + @PathVariable Long id@GetMapping("/buscar") + @RequestParam String genero
¿Es obligatorio?Sí: sin él, la ruta no existeNo, si le das defaultValue o required = false
Úsalo paraVer o editar un registroBuscar, filtrar, ordenar, paginar

2.1 Con la ruta: la ficha de un libro (/libros/7)

@GetMapping("/libros/{id}")
public String detalle(@PathVariable Long id, Model model) {
    model.addAttribute("libro", libroService.buscarPorId(id));   // el mismo método del Kit
    return "detalle";
}
<!-- templates/detalle.html (lo esencial) -->
<h2 th:text="${libro.titulo}">Título</h2>
<ul>
  <li>Autor: <span th:text="${libro.autor}">Autor</span></li>
  <li>ISBN: <span th:text="${libro.isbn}">978-0</span></li>
  <li th:text="${libro.disponible} ? 'Disponible para préstamo' : 'No disponible'">Disponible</li>
</ul>

<!-- y en lista.html, el título se vuelve un enlace a esa ficha: -->
<a th:href="@{/libros/{id}(id=${libro.id})}" th:text="${libro.titulo}">Título</a>
Probado: /libros/1 → 200. /libros/abc → 400 (no se puede convertir «abc» en número). /libros/99 (no existe) → 500, porque buscarPorId lanza una excepción: tu error.html lo muestra con el código. Es el mismo comportamiento de «Editar» en el Kit; en la Semana 16 (QA) se puede mejorar.

2.2 Con la consulta: filtrar por género (/buscar?genero=Novela)

// LibroRepository: Spring Data escribe la consulta SOLO a partir del nombre del método
List<Libro> findByGeneroIgnoreCase(String genero);

// LibroService
public List<Libro> buscarPorGenero(String genero) {
    if (genero.isBlank()) {
        return repositorio.findAll();          // sin filtro: todos
    }
    return repositorio.findByGeneroIgnoreCase(genero);
}

// Controlador
@GetMapping("/buscar")
public String buscar(@RequestParam(defaultValue = "") String genero, Model model) {
    var resultados = libroService.buscarPorGenero(genero);
    model.addAttribute("libros", resultados);
    model.addAttribute("total", resultados.size());
    return "lista";                            // REUTILIZA la plantilla de la lista
}

Fíjate en la última línea: reutilizas lista.html; solo cambia qué libros se le entregan. Así una nueva «página» casi no cuesta nada.

Probado: con un libro de género «Novela», /buscar?genero=novela lo muestra (ignora mayúsculas), /buscar?genero=Cuento no, y /buscar sin parámetro muestra todos.

2.3 Cómo se pone el enlace o el buscador

<!-- Enlace con parámetro: genera /buscar?genero=Novela -->
<a th:href="@{/buscar(genero='Novela')}">Ver novelas</a>

<!-- Buscador: un formulario GET (NO lleva _csrf, porque no modifica datos) -->
<form th:action="@{/buscar}" method="get">
  <select name="genero">
    <option value="">Todos</option>
    <option value="Novela">Novela</option>
    <option value="Cuento">Cuento</option>
  </select>
  <button type="submit">Buscar</button>
</form>
Un formulario GET pone sus campos en la dirección (?genero=Novela): el resultado se puede copiar y compartir. Un formulario POST es para guardar o cambiar cosas y siempre lleva CSRF. Regla: leer = GET; cambiar = POST.

🔐 Seguridad de las páginas nuevas (conecta con la auditoría)

  • Por defecto todo exige sesión. /libros/7 y /buscar funcionan solo con login (anyRequest().authenticated()). Haz pública únicamente la que debe serlo (créditos).
  • Los parámetros son datos del visitante: nunca los imprimas con th:utext. Con th:text un ?genero=<script> se muestra como texto inofensivo (XSS bloqueado).
  • Leer con GET, cambiar con POST: una página que borra o guarda al abrir un enlace (GET) se salta la protección CSRF. En este proyecto eliminar es POST + _csrf: no lo cambies.
  • Si tu página nueva está en una ruta con regla de rol (/libros/nuevo), conserva esa regla antes que las generales.
