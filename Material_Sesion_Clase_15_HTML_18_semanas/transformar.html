Del Kit de la Semana 14 a tu proyecto (ejemplo: ficha única «Libro» de una Biblioteca)

Esta página es una receta, no una tarea nueva. Muestra, paso a paso, cómo se convierte Jugador (3 campos) en Libro (13 campos) sin relaciones: una sola ficha con toda la información. El código mostrado fue compilado y probado (guardar, validar, editar, parámetros y 403 por CSRF) en una copia del Kit. Tu entidad tendrá otro nombre; el método es idéntico.

1️⃣ La entidad: de 3 a 13 campos

Cada campo es una línea de atributo más sus anotaciones, más su get y su set. Lo que ya sabes de las Semanas 11 y 12 (@NotBlank, @Min, @Column) es todo lo que se usa.

Antes · Jugador

3 campos: nombre (String), edad (Integer), posicion (String).

Ahora · Libro

13 campos de tipos distintos: texto, entero, decimal, fecha, sí/no y texto largo.

Qué sigue igual

@Entity, el id con IDENTITY, el constructor vacío y los getters y setters.
package gt.edu.url.biblioteca.model;   // tu paquete (el del Artifact, sin guion)

import java.math.BigDecimal;
import java.time.LocalDate;
import jakarta.persistence.*;
import jakarta.validation.constraints.*;

@Entity
public class Libro {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // ---- TEXTO obligatorio ----
    @NotBlank(message = "El título es obligatorio.")
    @Size(max = 120, message = "El título admite hasta 120 caracteres.")
    @Column(nullable = false, length = 120)
    private String titulo;

    @NotBlank(message = "El autor es obligatorio.")
    @Size(max = 80, message = "El autor admite hasta 80 caracteres.")
    @Column(nullable = false, length = 80)
    private String autor;

    // ---- CÓDIGO con formato: es String, no número ----
    @NotBlank(message = "El ISBN es obligatorio.")
    @Pattern(regexp = "[0-9-]{10,17}", message = "El ISBN lleva de 10 a 17 dígitos o guiones.")
    @Column(nullable = false, length = 17)
    private String isbn;

    // ---- TEXTO opcional: sin @NotBlank y sin nullable=false ----
    @Size(max = 60, message = "La editorial admite hasta 60 caracteres.")
    @Column(length = 60)
    private String editorial;

    // ---- ENTEROS ----
    @NotNull(message = "El año de publicación es obligatorio.")
    @Min(value = 1450, message = "El año mínimo es 1450.")
    @Max(value = 2100, message = "El año máximo es 2100.")
    @Column(nullable = false)
    private Integer anioPublicacion;

    @Min(value = 1, message = "El libro debe tener al menos 1 página.")
    private Integer numeroPaginas;            // opcional

    // ---- OPCIÓN de una lista fija (select): String ----
    @NotBlank(message = "Elige un género.")
    @Column(nullable = false)
    private String genero;

    @NotBlank(message = "Elige un idioma.")
    @Column(nullable = false)
    private String idioma;

    @NotNull(message = "Indica cuántos ejemplares hay.")
    @Min(value = 0, message = "Los ejemplares no pueden ser negativos.")
    @Column(nullable = false)
    private Integer ejemplares;

    // ---- DINERO: BigDecimal, nunca double ----
    @DecimalMin(value = "0.00", message = "El precio no puede ser negativo.")
    @Column(precision = 10, scale = 2)
    private BigDecimal precio;                // opcional

    // ---- FECHA ----
    @NotNull(message = "La fecha de ingreso es obligatoria.")
    @PastOrPresent(message = "La fecha de ingreso no puede ser futura.")
    @Column(nullable = false)
    private LocalDate fechaIngreso;

    // ---- SÍ / NO ----
    private boolean disponible = true;

    // ---- TEXTO LARGO ----
    @Size(max = 500, message = "El resumen admite hasta 500 caracteres.")
    @Column(length = 500)
    private String resumen;

    public Libro() { }

    // Getters y setters de CADA campo (VS Code los genera: clic derecho → Source Action → Generate Getters and Setters).
    // Ojo: el boolean usa isDisponible()/setDisponible(...)
}
¿Por qué estas decisiones?
  • Sin relaciones: no hay @OneToMany ni clases extra (autor, préstamo…). El autor es solo un texto. Eso es lo que hace posible terminar a tiempo.
  • Doble candado en lo obligatorio: @NotBlank/@NotNull muestra el mensaje bonito; nullable = false lo exige la base.
  • boolean con valor inicial true: al abrir «Registrar libro», la casilla aparece marcada.
  • ¿Cuántos campos? Entre 10 y 15. Más es más trabajo de formulario sin más aprendizaje.

2️⃣ Repositorio, servicio y controlador: solo cambian los nombres

Son las mismas tres clases del Kit. Se muestra el repositorio completo; en el servicio y el controlador se reemplaza Jugador→Libro, jugador→libro y /jugadores→/libros.

public interface LibroRepository extends JpaRepository<Libro, Long> {
}

// Controlador: solo cambian los nombres y las rutas
@GetMapping({"/", "/libros"})          public String listar(Model model) { … }
@GetMapping("/libros/nuevo")           public String nuevo(Model model)  { … }
@GetMapping("/libros/{id}/editar")     public String editar(@PathVariable Long id, Model model) { … }
@PostMapping("/libros")                public String guardar(@Valid @ModelAttribute("libro") Libro libro, BindingResult resultado) { … }
@PostMapping("/libros/{id}/eliminar")  public String eliminar(@PathVariable Long id) { … }
No olvides SecurityConfig: sus reglas nombran las rutas ("/jugadores/nuevo", "/jugadores/*/editar", "/jugadores/**"). Si cambias el controlador a /libros y no cambias estas tres, el administrador recibiría error de acceso o, peor, las rutas quedarían sin la regla de rol. Sustitúyelas por "/libros/nuevo", "/libros/*/editar" y "/libros/**".

3️⃣ El formulario: un bloque por campo

Cada campo repite el mismo patrón de tres líneas: etiqueta, input y mensaje de error. Lo único que cambia es el nombre del campo y el type del input (ver la tabla de tipos).

<!-- Texto -->
<label for="titulo">Título</label>
<input id="titulo" type="text" th:field="*{titulo}" th:errorclass="campo-error">
<p class="mensaje-error" th:if="${#fields.hasErrors('titulo')}" th:errors="*{titulo}">Error</p>

<!-- Número entero -->
<input id="anioPublicacion" type="number" th:field="*{anioPublicacion}" th:errorclass="campo-error">

<!-- Decimal (dinero) -->
<input id="precio" type="number" step="0.01" th:field="*{precio}" th:errorclass="campo-error">

<!-- Fecha -->
<input id="fechaIngreso" type="date" th:field="*{fechaIngreso}" th:errorclass="campo-error">

<!-- Lista fija -->
<select id="genero" th:field="*{genero}">
  <option value="Novela">Novela</option>
  <option value="Cuento">Cuento</option>
</select>

<!-- Sí / No -->
<label><input type="checkbox" th:field="*{disponible}"> Disponible para préstamo</label>

<!-- Texto largo -->
<textarea id="resumen" rows="4" th:field="*{resumen}"></textarea>
Dos reglas que no se negocian: (1) el <form> sigue usando th:action="@{/libros}" (así lleva el _csrf); (2) th:field="*{…}" debe llamarse exactamente como el atributo de la entidad, con la misma ortografía y mayúsculas.

4️⃣ La lista: elige qué mostrar

Una tabla con 13 columnas no cabe en un celular. Muestra 3 o 4 en la lista (las más útiles para reconocer un registro) y deja el resto para el formulario o la página de detalle (ver Páginas nuevas).

<tr><th>Id</th><th>Título</th><th>Autor</th><th>Año</th></tr>
…
<tr th:each="libro : ${libros}">
  <td th:text="${libro.id}">1</td>
  <td th:text="${libro.titulo}">Título</td>
  <td th:text="${libro.autor}">Autor</td>
  <td th:text="${libro.anioPublicacion}">1998</td>
  …

⚠️ Antes de hacer git push: lo que pasa con Neon

Tu tabla en Neon ya existe con las columnas del Kit. Con ddl-auto=update Hibernate agrega columnas, pero nunca borra ni renombra. Tres situaciones:

Si tú…Entonces…Haz esto
Cambias el nombre de la entidad (Jugador → Libro)Se crea una tabla libro nueva y vacía; jugador queda abandonada.Normal. Opcional: borrar la tabla vieja en Neon → Tables.
Agregas columnas opcionales a una tabla con filasSe agregan con valor vacío.Nada.
Agregas columnas obligatorias (nullable = false) a una tabla con filasEl despliegue falla: column "x" of relation "y" contains null values.Vacía la tabla en Neon antes de desplegar (en este curso los datos son de prueba).
Orden seguro: 1) cambia el código y pruébalo en tu computadora (perfil dev, H2: si falla, borra la carpeta datos/); 2) vacía la tabla vieja en Neon; 3) git push; 4) mira el log de Render hasta ver Live; 5) registra un libro de prueba y reinicia para confirmar que sobrevive.

✅ Resumen: tu receta en 8 pasos

  1. Lee la Ficha de tu Proyecto y decide el nombre de tu entidad.
  2. Llena la tabla de campos en el Checkpoint ★ (Parte B): 10–15 campos, tipo, obligatorio, validación.
  3. Renombra las clases (modelo, repositorio, servicio, controlador).
  4. Escribe los campos en la entidad con sus anotaciones.
  5. Actualiza formulario.html, lista.html, error.html y login.html.
  6. Actualiza las rutas en SecurityConfig.
  7. Prueba en tu computadora (dev) y recorre: crear, editar, eliminar, error de validación, entrenador sin permiso.
  8. Vacía la tabla en Neon, haz git push y verifica en la URL de Render.
