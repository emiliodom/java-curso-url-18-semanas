Un simulador que sí funciona, capa por capa

Abajo hay una lista de tareas de un voluntariado que funciona de verdad, en tu navegador, construida con las 4 capas de hoy (Vista, Controlador, Servicio, Repositorio). Interactúa con ella antes de resolver los ejercicios.

🔧 Simulador: Lista de tareas del voluntariado

Regla activa: máximo 5 tareas, y ninguna puede quedar vacía.

Tareas guardadas (Repositorio)

    Ver el código de las 4 capas (JavaScript real, el que se está ejecutando) 
    // ENTIDAD (el dato puro)
// una tarea es simplemente: { texto: "..." }

// REPOSITORIO — solo guarda y entrega, no decide nada
var Repositorio = {
  tareas: [],
  guardar: function (tarea) { this.tareas.push(tarea); },
  listarTodas: function () { return this.tareas; }
};

// SERVICIO — aplica las reglas de negocio
var Servicio = {
  agregarTarea: function (texto) {
    if (!texto || !texto.trim()) {
      return { ok: false, error: "La tarea no puede estar vacía." };
    }
    if (Repositorio.listarTodas().length >= 5) {
      return { ok: false, error: "Ya hay 5 tareas — límite alcanzado." };
    }
    Repositorio.guardar({ texto: texto.trim() });
    return { ok: true };
  }
};

// CONTROLADOR — recibe el clic, le pregunta al SERVICIO (nunca al Repositorio)
function onAgregarTarea() {
  var texto = document.getElementById("taskInput").value; // lee de la Vista
  var resultado = Servicio.agregarTarea(texto);            // le pregunta al Servicio
  if (resultado.ok) { renderizarVista(); }                  // decide qué mostrar
  else { mostrarError(resultado.error); }
}

// VISTA — solo muestra, no decide ni valida

    Antes de empezar: la pregunta ancla de esta semana
    En cada ejercicio pregúntate: ¿el Controlador le habló al Servicio, o se saltó directo al Repositorio? Si el Controlador respeta esa regla, el bajo acoplamiento está funcionando.

    Ejercicio 1 — Observa el camino feliz Calentamiento

    Escribe una tarea válida (ej. "Llamar a donantes") y pulsa "Agregar". Mira el registro de capas.

    Tu turno: en orden, ¿qué capa actúa primero y cuál actúa al final?

    Solución
    Primero el Controlador (recibe el clic), luego el Servicio (valida), luego el Repositorio (guarda), y al final la Vista (muestra la lista actualizada).

    Ejercicio 2 — Provoca el error de "vacío" Regla

    Deja el campo de texto vacío y pulsa "Agregar".

    Tu turno: ¿qué capa detuvo la operación, y qué capa NUNCA llegó a actuar?

    Solución
    El Servicio detuvo la operación (aplicó la regla). El Repositorio nunca llegó a actuar — nunca se guardó nada inválido.

    Ejercicio 3 — Provoca el límite de 5 Regla

    Agrega tareas válidas hasta llegar a 5, y luego intenta una sexta.

    Tu turno: ¿en qué capa vive la regla "máximo 5 tareas"?

    Solución
    Vive en el Servicio — es una regla de negocio, igual que la validación de vacío. El Repositorio solo cuenta cuántas hay cuando el Servicio se lo pregunta.

    Ejercicio 4 — Lee el código del Servicio Código real

    Abre "Ver el código" arriba y localiza la línea if (Repositorio.listarTodas().length >= 5).

    Tu turno: si quisiéramos permitir hasta 10 tareas en vez de 5, ¿qué línea cambiarías, y en qué capa vive ese cambio?

    Solución
    Cambiarías el número 5 por 10 en esa línea, dentro del Servicio. Ni el Controlador ni el Repositorio necesitan tocarse.

    Ejercicio 5 — Verifica el bajo acoplamiento Código real

    Lee la función onAgregarTarea() (el Controlador) en el código de arriba.

    Tu turno: ¿en algún punto llama directo a Repositorio? Justifica tu respuesta citando la línea exacta.

    Solución
    No. El Controlador solo llama a Servicio.agregarTarea(texto) y a renderizarVista()/mostrarError(). Nunca escribe Repositorio.algo() directamente — por eso respeta el bajo acoplamiento.

    Ejercicio 6 — ¿Qué pasaría si...? Antipatrón

    Imagina que alguien reescribe el Controlador así: onAgregarTarea() { Repositorio.guardar({texto: ...}); renderizarVista(); } (sin pasar por el Servicio).

    Tu turno: en una frase, ¿qué reglas dejarían de cumplirse?

    Solución
    Se podrían guardar tareas vacías y se podría superar el límite de 5 — ambas reglas viven en el Servicio, que quedó completamente evitado. Es el antipatrón de "saltarse capas".

    Ejercicio 7 — Reto integrador: diseña una regla nueva Integrador

    El voluntariado pide una regla nueva: "no se puede agregar una tarea con el mismo texto que otra ya existente".

    Tu turno: ¿en qué capa la implementarías, y qué necesitarías preguntarle a otra capa para poder aplicarla?

    Ejemplo de solución
    Se implementa en el Servicio: antes de guardar, le pregunta al Repositorio (listarTodas()) si ya existe una tarea con ese mismo texto, y si es así, devuelve un error — igual que hace ya con la regla del límite de 5.
