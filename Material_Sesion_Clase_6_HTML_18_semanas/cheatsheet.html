Referencia rápida — Servicio, Repositorio y tu entorno

Dos pestañas: conceptos de arquitectura, y una revisión paso a paso de tu entorno de cara a la Semana 7 (Spring Boot).

A. La analogía extendida del restaurante

En el restauranteEn la aplicaciónCapa grande
🍽️ El menú y las mesasVistaPresentación
🧑‍💼 El meseroControlador
👨‍🍳 El chef ejecutivo: aplica recetas y decide qué pedir a la bodegaServicioNegocio
📦 La bodega: guarda y entrega, no decideRepositorioDatos
🥫 El ingrediente mismoEntidad

B. Responsabilidades: qué SÍ y qué NUNCA

RolSÍ haceNUNCA hace
VistaMostrar datos, recibir clics/entradasValidar reglas o decidir el flujo
ControladorRecibir la acción, preguntarle al Servicio, elegir la VistaValidar reglas él mismo, o hablar directo con el Repositorio
ServicioAplicar reglas de negocio, coordinar con el RepositorioDibujar pantallas o saber de botones
RepositorioGuardar y recuperar datosAplicar reglas de negocio
EntidadRepresentar el dato puro (atributos)Contener lógica de negocio o de acceso a datos

C. Ejemplo aplicado: registro de un beneficiario

ENTIDAD (Beneficiario): nombre, edad, fecha de ingreso

REPOSITORIO (BeneficiarioRepositorio): guardar(), buscarPorId(), listarTodos()
        (solo lee/escribe, no valida nada)

SERVICIO (BeneficiarioServicio): registrar(datos)
        → valida "edad entre 0 y 120"
        → si es válida, le pide al Repositorio que guarde

CONTROLADOR (RegistroController): recibe el clic en "Guardar"
        → le pide al SERVICIO que registre (nunca al Repositorio)
        → decide qué Vista mostrar según la respuesta

D. Bajo acoplamiento: la regla del mesero

✅ Correcto
Vista → Controlador → Servicio → Repositorio → Entidad
🚫 Antipatrón: "saltarse capas"
Vista → Controlador → Servicio → Repositorio (¡nadie validó nada!)
El Controlador solo le habla al Servicio. Si mañana cambias cómo se guardan los datos, el Controlador ni se entera — esa independencia es el "bajo acoplamiento".

F. Relación con frameworks modernos (vista previa de Spring Boot)

Todavía no instalas nada — la Semana 7 empieza el código real. Esto es solo para que el vocabulario ya te suene familiar:

H. Confusiones frecuentes

ConfusiónAclaración
"¿El Servicio reemplaza al Modelo de la semana pasada?"No lo reemplaza: lo divide. El "Modelo" de la Semana 5 = Entidad + Repositorio + Servicio juntos.
"¿El Servicio puede hablar con el Repositorio?"Sí, siempre. Lo que nunca ocurre es que el Controlador hable directo con el Repositorio.
"¿Cuántos Servicios/Repositorios tiene una app?"Normalmente uno de cada uno por Entidad (ej. BeneficiarioServicio, BeneficiarioRepositorio).
"¿Esto ya es Spring Boot?"No todavía — es diseño y diagrama. El código real empieza en la Semana 7.
¿Por qué revisar esto ahora?
La Semana 7 empieza código real con Spring Boot. Si tu entorno (VS Code + JDK) ya estaba listo desde la Semana 1, esto es solo un repaso de 5 minutos. Si algo quedó pendiente, este es el momento de resolverlo — sin prisa, con calma.

Checklist de preparación

1
Verifica que Java (JDK) esté instalado
Abre una terminal (ver Semana 1 — Paso 3 si no sabes cómo) y escribe:
java -version
javac -version
✅ Checkpoint: ambos comandos deben responder con un número de versión (ej. "21.0.x"), no con un error de "comando no encontrado".
2
Confirma que VS Code esté instalado
Abre VS Code. Si no lo tienes, sigue Semana 1 — Paso 1. ✅ Checkpoint: la aplicación abre sin errores.
3
Confirma la extensión "Extension Pack for Java"
En VS Code: ícono de Extensiones (barra lateral izquierda) → busca "Extension Pack for Java" (de Microsoft) → debe decir "Instalado" (si no, clic en "Install"). ✅ Checkpoint: aparece "Installed" junto al nombre.
4
Crea y corre un archivo de prueba
Crea un archivo Prueba.java en una carpeta nueva, con este contenido:
public class Prueba {
    public static void main(String[] args) {
        System.out.println("Entorno listo para la Semana 7");
    }
}
Guarda, y busca el botón ▶ Run que aparece arriba del método main (lo agrega la extensión de Java). Clic ahí. ✅ Checkpoint: en la terminal integrada aparece el mensaje "Entorno listo para la Semana 7".
5
Confirma tu GitHub Desktop (o Git) y tu repositorio del proyecto
Abre tu repositorio real (Semana 3) en GitHub Desktop y confirma que sigues teniendo acceso sin problemas — lo necesitarás para subir tu código real desde la Semana 7.
Solución de problemas frecuentes
SituaciónQué hacer
"java no se reconoce como un comando"El JDK no está instalado o no está en el PATH. Repite Semana 1 — Paso 2.
El botón "▶ Run" no aparece sobre mainVerifica que el archivo termine en .java y que "Extension Pack for Java" esté instalado y activo (reinicia VS Code).
VS Code pide "seleccionar un JDK"Elige el que ya tienes instalado de la lista; si no aparece ninguno, reinstala el JDK y reinicia VS Code.
No tengo tiempo/permisos para instalar en esta computadoraUsa el compilador en línea (Plan B, Semana 1) mientras resuelves la instalación real antes de la Semana 7.
¿Todo listo?
Si los 5 pasos tienen su ✅, tu entorno está listo para la Semana 7. Si algo falla, es normal — vuelve a la guía de instalación completa de la Semana 1 con calma durante la semana.
