El antipatrón que hay que saber nombrar: "saltarse capas"
Ocurre cuando una capa habla con otra que no le corresponde (por ejemplo, el controlador armando reglas de negocio, o la vista calculando datos). La cadena correcta es: Vista → Controlador → Servicio → (Repositorio), y de regreso.

El recorrido de una petición, en una línea
El navegador pide una URL → el DispatcherServlet de Spring busca un método cuya ruta coincida exactamente → si lo encuentra, ejecuta tu método y devuelve su resultado; si no, responde 404.

🌐 Ambientes de trabajo: desarrollo y producción

Este tema sí entra al examen aunque no se haya trabajado con código: es vocabulario profesional básico, y como futuros docentes de tecnología les va a tocar explicarlo. Un mismo sistema vive en copias separadas, cada una con un propósito:

AmbientePara qué esQuién lo usaCon qué datos
DesarrolloEscribir y probar código nuevo; aquí se rompen cosas a propósitoQuien programaDatos inventados de prueba
PruebasRevisar que lo nuevo funcione antes de publicarloEl equipo, antes de publicarDatos de prueba parecidos a los reales
ProducciónLa versión que está en uso de verdadLas personas de la instituciónDatos reales

Tu proyecto vive hoy en desarrollo: corre en localhost, en tu computadora. Cuando lo publiquemos en internet (Semana 14) existirá también su versión de producción.

La regla de oro: no se toca producción "en caliente"
Modificar directamente los archivos de producción mientras la gente está usando el sistema es una de las peores prácticas que existen: si el cambio falla, el sistema se cae para todos y no hay forma ordenada de regresar. El camino correcto siempre es el mismo: se cambia en desarrollo → se prueba → se publica a producción, y el historial queda en Git por si hay que revertir. Es exactamente para lo que sirven las ramas que usas desde la Semana 4.

Por qué esta pestaña existe
En las Semanas 7 y 8 vimos anotaciones sueltas (@RestController, @GetMapping) sin detenernos en las dos líneas que van antes de todo archivo Java: el package y los import. Son la causa de la mayoría de los "no me funciona y no sé por qué". Aquí están explicadas de una vez y para siempre.

A. Las cuatro partes de todo archivo Java

package gt.edu.url.repasospring.controller;          ← 1. DÓNDE vive este archivo

import org.springframework.web.bind.annotation.GetMapping;      ← 2. QUÉ necesita
import org.springframework.web.bind.annotation.RestController;

@RestController                                      ← 3. QUÉ ES para Spring
public class BienvenidaController {                  ← 4. EL CÓDIGO

    @GetMapping("/api/saludo")
    public String saludo() {
        return "¡Bienvenido(a)!";
    }
}
#ParteRegla
1packageSiempre la primera línea. Debe coincidir con la carpeta real del archivo.
2importUno por cada clase o anotación "de afuera" que uses. Valen para todo el archivo.
3AnotaciónLe dice a Spring qué papel juega la clase. Requiere su import.
4ClaseEl nombre de la clase debe ser idéntico al nombre del archivo (sin .java).

B. Carpeta = paquete (la traducción exacta)

Carpeta real:   src/main/java/gt/edu/url/repasospring/controller/BienvenidaController.java
                              └───┬──┘ └┬┘ └┬┘ └─────┬─────┘ └────┬────┘
Línea package:  package        gt   .  edu . url . repasospring . controller ;
Cada / de la carpeta es un . en el paquete. Todo lo que va después de src/main/java/ forma el nombre del paquete; el nombre del archivo no entra.
Los dos errores distintos que produce equivocarse aquí
(1) No coinciden carpeta y package: el proyecto no compila, VS Code lo marca en rojo de inmediato. Molesto pero fácil de ver.
(2) Coinciden, pero el archivo quedó fuera del paquete base: el proyecto compila y arranca sin una sola advertencia… y la ruta responde 404. Este es el difícil, porque nada te avisa.

C. Por qué un endpoint correcto puede "no existir"

@SpringBootApplication hace, entre otras cosas, un escaneo de componentes: revisa su propio paquete y todos los subpaquetes, buscando clases anotadas. Lo que quede fuera de esa rama, no existe para Spring.

gt.edu.url.repasospring            ← aquí está ...Application.java (paquete base)
├── controller  ✅ Spring lo revisa   (está debajo del paquete base)
├── service     ✅ Spring lo revisa
├── model       ✅ Spring lo revisa
│
gt.edu.url.otro                    ❌ Spring NO lo revisa (está fuera de la rama)
Regla práctica para no fallar nunca
Crea todas tus carpetas dentro de la carpeta que contiene tu archivo ...Application.java. Si tu controlador está al lado de esa clase o en una subcarpeta suya, Spring siempre lo encontrará.

D. Cuándo hace falta un import y cuándo no

Situación¿Necesita import?Ejemplo

Otra clase del mismo paqueteNoDos clases dentro de …/service/
Clase tuya en otro paqueteSíimport gt.edu.url.repasospring.model.Visitante;

Utilidades de Java (java.util)Síimport java.util.List;

Los imports que vas a usar esta semana, tal cual

// Para la clase principal (ya vienen escritos)
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

// Para un controlador REST
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

// Para un servicio
import org.springframework.stereotype.Service;
No los memorices: deja que VS Code los escriba
Escribe la anotación (por ejemplo @Service); aparecerá subrayada en rojo. Pon el cursor encima, pulsa Ctrl+. y elige la opción "Import…". VS Code agrega la línea correcta arriba. Para ordenarlos todos: Shift+Alt+O.

Errores de Java y Spring Boot

Mensaje o síntomaQué significaCómo se arregla
🔇 La ruta responde 404 (Whitelabel) pero el código está bien Spring nunca registró tu controlador: quedó fuera del paquete base Mueve la clase dentro del paquete de tu ...Application.java (o una subcarpeta) y ajusta la línea package.
🔇 La ruta responde 404 y el controlador sí está bien ubicado La URL no coincide letra por letra con @GetMapping Compara mayúsculas, acentos, guiones y la barra inicial. /api/Saludo ≠ /api/saludo.
cannot find symbol: class RestController Falta el import de esa anotación Ctrl+. sobre la palabra subrayada → "Import…".
The declared package … does not match the expected package … La línea package no corresponde a la carpeta del archivo Corrige la línea package (o mueve el archivo a la carpeta que esa línea indica).
Web server failed to start. Port 8080 was already in use. Otra copia del proyecto sigue corriendo Detén la anterior con Ctrl+C en su terminal, o pon server.port=8081 en application.properties.
class … is public, should be declared in a file named ….java El nombre de la clase y el del archivo no son iguales Renombra el archivo o la clase para que coincidan exactamente, mayúsculas incluidas.
Parameter 0 of constructor … required a bean of type … that could not be found El controlador pide un servicio que Spring no conoce Verifica que la clase del servicio tenga @Service y esté dentro del paquete base.
Required request parameter 'nombre' is not present El parámetro es obligatorio y no vino en la URL Agrega @RequestParam(defaultValue = "…") o incluye siempre el parámetro.
El botón ▶ Run no aparece sobre main VS Code no reconoció el proyecto como Maven/Java Abre la carpeta raíz (la que tiene pom.xml), no una subcarpeta.
Cambié el código pero el navegador muestra lo anterior El proyecto no se reinició, o es caché del navegador Detén y vuelve a ejecutar; refresca con Ctrl+F5.

Antes de pedir ayuda, ten esto listo
(1) El mensaje de error completo (copiado, no descrito). (2) La ruta exacta del archivo donde ocurre. (3) Qué cambiaste justo antes de que dejara de funcionar. Con esas tres cosas, casi cualquier error de esta lista se resuelve en un minuto — y es, además, la forma profesional de reportar un problema.
