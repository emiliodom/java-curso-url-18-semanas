Ejercicios · Semana 9 · Repaso integrado de las 8 semanas

Ocho ejercicios en escalera — y todo el código, completo

Dos pestañas: los ejercicios, que suben de dificultad paso a paso, y el Kit de archivos completos, donde cada archivo aparece entero — con su línea package, sus import y la ruta exacta de la carpeta donde va. Proyecto de práctica: repaso-spring · Institución de ejemplo: Banco de Alimentos San Miguel.
Cómo está armada esta escalera
Los ejercicios van de menos a más: los primeros se resuelven en un minuto, los últimos exigen juntar varias piezas. Ninguno pide algo que no se haya visto entre las Semanas 1 y 8. Si te trabas en cualquiera, el Kit de archivos completos tiene el archivo entero para comparar contra el tuyo.
La pregunta ancla de esta semana
Antes de pedir ayuda con un endpoint que "no funciona", pregúntate las tres cosas en este orden: (1) ¿el archivo está dentro del paquete base del proyecto? (2) ¿la línea package coincide exactamente con la carpeta donde está el archivo? (3) ¿están los import que necesitan las anotaciones? El 90% de los errores de las Semanas 7 y 8 fueron una de esas tres.

Ejercicio 1 — Tu entorno sigue vivo Nivel 1

Abre una terminal y ejecuta los tres comandos de verificación:

java -version
git --version
code --version

Tu turno: ¿los tres responden con un número de versión?

✅ Checkpoint: los tres comandos responden. Si alguno falla, resuélvelo antes de seguir — todo lo demás depende de ellos.
Solución
Debes ver algo como openjdk version "21...", git version 2.x y una versión de VS Code. Si java no se reconoce, repite el Paso 2 de la Semana 1.

Ejercicio 2 — Java puro: lee y predice Nivel 1

Este archivo va en src/main/java/gt/edu/url/repasospring/Practica.java:

package gt.edu.url.repasospring;

public class Practica {
    public static void main(String[] args) {
        int donaciones = 7;
        String institucion = "Banco de Alimentos San Miguel";

        for (int i = 1; i <= 3; i++) {
            donaciones = donaciones + 5;
        }

        if (donaciones >= 20) {
            System.out.println(institucion + ": meta alcanzada (" + donaciones + ")");
        } else {
            System.out.println(institucion + ": faltan " + (20 - donaciones));
        }
    }
}

Tu turno: predice la salida antes de ejecutarlo. Luego ejecútalo con el botón ▶ Run.

Solución
El ciclo suma 5 tres veces: 7 + 15 = 22. Como 22 ≥ 20, imprime Banco de Alimentos San Miguel: meta alcanzada (22).
Fíjate: este archivo no tiene ningún import, y funciona. String y System vienen de java.lang, que Java incluye siempre sin pedirlo.

Ejercicio 3 — Anatomía: carpeta = paquete Nivel 2

Copia del Kit el archivo BienvenidaController.java a su ruta correcta y ejecuta el proyecto. Confirma que localhost:8080/api/saludo responde.

Ahora rómpelo a propósito: cambia solo la primera línea del archivo, de package gt.edu.url.repasospring.controller; a package gt.edu.url.otro; (sin mover el archivo de carpeta).

Tu turno: ¿qué error aparece y por qué?

✅ Checkpoint: entiendes que la línea package debe reflejar la carpeta real del archivo. Deja el archivo como estaba antes de continuar.
Solución
VS Code marca el archivo en rojo con un mensaje del tipo The declared package "gt.edu.url.otro" does not match the expected package "gt.edu.url.repasospring.controller", y el proyecto no compila. La regla es literal: la ruta de carpetas y la línea package son la misma cosa escrita de dos maneras — carpetas separadas por /, paquete separado por puntos.

Ejercicio 4 — El endpoint invisible Nivel 2

Con el proyecto funcionando, mueve la carpeta controller completa fuera del paquete base: de src/main/java/gt/edu/url/repasospring/controller/ a src/main/java/gt/edu/url/controller/, y corrige la línea package para que coincida (package gt.edu.url.controller;). El proyecto sí compila. Ejecútalo y visita /api/saludo.

Tu turno: el código compila sin errores… pero la ruta responde 404. ¿Por qué?

✅ Checkpoint: sabes distinguir "error de compilación" de "endpoint que Spring nunca encontró". Regresa la carpeta a su lugar y confirma que vuelve a responder.
Solución
@SpringBootApplication le dice a Spring: "busca componentes en mi paquete y en todo lo que cuelgue debajo". Tu clase ...Application.java está en gt.edu.url.repasospring, así que Spring revisa gt.edu.url.repasospring.*. Al mover el controlador a gt.edu.url.controller, quedó fuera de esa rama: Java lo compila igual, pero Spring nunca lo registra y la ruta no existe.
Esta es la causa más común de "mi endpoint no funciona y no entiendo por qué": no hay mensaje de error, simplemente el 404. Regla práctica: todas tus clases van dentro del paquete de la clase Application, o en subcarpetas de ella.

Ejercicio 5 — Escribe un endpoint sin copiar Nivel 3

En BienvenidaController, agrega un tercer método que responda en /api/horario con el horario de atención del Banco de Alimentos (inventa el texto). Escríbelo tú, sin copiar del Kit.

Tu turno: ¿necesitaste agregar algún import nuevo? ¿Por qué sí o por qué no?

✅ Checkpoint: /api/horario responde tu texto en el navegador.
Solución
No hace falta ningún import nuevo: @GetMapping ya estaba importado para los otros métodos, y un import sirve para todo el archivo, no por método. 
@GetMapping("/api/horario")
public String horario() {
    return "Atendemos de lunes a viernes, de 8:00 a 16:00.";
}
Truco de VS Code: si escribes una anotación y aparece subrayada en rojo, pulsa Ctrl+. sobre ella y elige "Import…" — el editor agrega la línea correcta por ti.

Ejercicio 6 — Dos parámetros a la vez Nivel 3

Agrega un método en /api/donacion que reciba dos parámetros: nombre (texto, por defecto "anónimo") y libras (número entero, por defecto 0), y devuelva un mensaje de agradecimiento que los use.

Tu turno: pruébalo con /api/donacion?nombre=Ana&libras=12. ¿Qué separa un parámetro del siguiente en la URL?

✅ Checkpoint: la ruta responde usando ambos valores, y también responde (con los valores por defecto) si la visitas sin parámetros.
Solución
Los parámetros se separan con &. El primero va después de ?. 
@GetMapping("/api/donacion")
public String donacion(
        @RequestParam(defaultValue = "anónimo") String nombre,
        @RequestParam(defaultValue = "0") int libras) {
    return "Gracias, " + nombre + ", por donar " + libras + " libras de alimento.";
}
Fíjate que defaultValue siempre se escribe entre comillas ("0"), aunque el parámetro sea un número: Spring lo convierte de texto a int por ti.

Ejercicio 7 — Las tres capas hablando Nivel 4

Copia del Kit los archivos Visitante.java (modelo) y BienvenidaService.java (servicio) a sus rutas, y ajusta el controlador para que le pida el mensaje al servicio en vez de armarlo él mismo (el Kit trae esa versión).

Tu turno: ¿qué línea del controlador demuestra que ya no arma el texto por su cuenta? ¿Qué capa quedó a cargo de esa decisión?

✅ Checkpoint: la aplicación responde igual que antes, pero ahora el texto lo decide el servicio. Esto es lo que la Entrega Parcial 2 llama "MVC funcional".
Solución
La línea es return bienvenidaService.mensajePara(nombre); — el controlador delega. La capa de negocio (el @Service) quedó a cargo del contenido del mensaje; el controlador solo recibe la petición y devuelve lo que el servicio le da. Es exactamente la separación de responsabilidades de la Semana 6: quien recibe no es quien decide.
Sobre el constructor: el controlador recibe el servicio por su constructor y Spring se lo entrega solo. No tienes que escribir new BienvenidaService() en ningún lado — esa es la parte que Spring automatiza por ti.

La regla de oro: carpeta = paquete
Un punto en el package equivale a una carpeta. package gt.edu.url.repasospring.controller; significa que el archivo está guardado en src/main/java/gt/edu/url/repasospring/controller/. 4. BienvenidaController.java lo creas tú

package gt.edu.url.repasospring.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import gt.edu.url.repasospring.service.BienvenidaService;

@RestController
public class BienvenidaController {

    private final BienvenidaService bienvenidaService;

    // Spring entrega el servicio automáticamente por este constructor.
    public BienvenidaController(BienvenidaService bienvenidaService) {
        this.bienvenidaService = bienvenidaService;
    }

    @GetMapping("/api/saludo")
    public String saludo() {
        return bienvenidaService.mensajeGeneral();
    }

    @GetMapping("/api/bienvenida")
    public String bienvenida(@RequestParam(defaultValue = "visitante") String nombre) {
        return bienvenidaService.mensajePara(nombre);
    }
}

5. BienvenidaService.java lo creas tú

Ruta: src/main/java/gt/edu/url/repasospring/service/BienvenidaService.java

La capa de negocio de la Semana 6, ahora en código: aquí se decide qué dice la aplicación.

package gt.edu.url.repasospring.service;

import org.springframework.stereotype.Service;

import gt.edu.url.repasospring.model.Visitante;

@Service
public class BienvenidaService {

    private static final String INSTITUCION = "Banco de Alimentos San Miguel";

    public String mensajeGeneral() {
        return "¡Bienvenido(a) al " + INSTITUCION + "!";
    }

    public String mensajePara(String nombre) {
        Visitante visitante = new Visitante(nombre);
        return "Hola, " + visitante.getNombre()
                + ". Gracias por apoyar al " + INSTITUCION + ".";
    }
}
@Service le avisa a Spring: "esta clase es una pieza de la aplicación, créala y entrégasela a quien la pida". Por eso el controlador puede recibirla en su constructor sin escribir new en ningún lado.

6. Visitante.java lo creas tú

Ruta: src/main/java/gt/edu/url/repasospring/model/Visitante.java

El modelo: datos puros, sin lógica ni anotaciones. Es la clase Java "de toda la vida" de la Semana 2.

package gt.edu.url.repasospring.model;

public class Visitante {

    private String nombre;

    public Visitante(String nombre) {
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }

    public void setNombre(String nombre) {
        this.nombre = nombre;
    }
}
Ningún import, ninguna anotación: solo usa String, que Java incluye siempre. Que un archivo no tenga imports no significa que esté incompleto.

    <p>Escribe tu nombre para recibir un saludo de nuestro equipo.</p>

    <form id="formBienvenida">
      <label for="nombre">Tu nombre:</label>
      <input type="text" id="nombre" name="nombre" required />
      <button type="submit">Enviar</button>
    </form>

    <p id="resultado"></p>
  </main>

  <script>
    document.getElementById('formBienvenida').addEventListener('submit', function (e) {
      e.preventDefault();
      var nombre = document.getElementById('nombre').value;

      fetch('/api/bienvenida?nombre=' + encodeURIComponent(nombre))
        .then(function (respuesta) { return respuesta.text(); })
        .then(function (texto) {
          document.getElementById('resultado').textContent = texto;
        })
        .catch(function () {
          document.getElementById('resultado').textContent =
            'No se pudo conectar con el servidor. ¿Está corriendo el proyecto?';
        });
    });
  </script>
</body>
</html>
El bloque .catch(...) es nuevo respecto a la Semana 8: muestra un mensaje claro si el servidor no responde, en vez de dejar la página en silencio. Es una mejora pequeña que se nota mucho en la evaluación entre pares.
