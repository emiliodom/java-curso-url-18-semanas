Entregable · Guía de Aprendizaje 4 · Trabajo autónomo (1 pt)

Rama de desarrollo y README profesional del proyecto

Completa esta plantilla durante la semana y súbela antes de la Sesión 5 (8 de agosto de 2026). Llena los campos, luego Exportar a PDF y súbelo al aula virtual como Guia4_TuNombre.pdf.

Datos del estudiante

Instrucciones generales
  1. Este entregable trabaja sobre el mismo repositorio de la Guía 3: no crees un repositorio nuevo.
  2. Sigue la guía paso a paso de Proyecto (rama development + README + Pull Request) antes de llenar esta plantilla.
  3. El dato más importante que debes entregar es el enlace a tu Pull Request (Parte D).
  4. Trabaja con autonomía: antes de preguntar, relee el mensaje en pantalla, consulta el cheat sheet e intenta de nuevo.

Parte A — Verificación de entorno (15%)

Confirma que trabajaste sobre tu repositorio real (no uno de práctica) y que main permanece estable.

Parte B — Rama development (25%)

Creaste la rama development con "Current Branch" → "New Branch" y trabajaste ahí, sin tocar main directamente.

Parte C — README.md profesional (30%)

Pega el contenido completo de tu README actualizado (debe incluir: nombre del proyecto, descripción de la entidad, funcionalidades planeadas, tecnologías, cómo clonar/ejecutar y autor — plantilla en cheat sheet, sección F).

Parte D — Pull Request y revisión (20%)

Publicaste la rama, abriste una Pull Request de development hacia main, y obtuviste (o hiciste) al menos un comentario de revisión antes de fusionar.

Parte E — Reflexión (10%)

  1. Disciplina en el flujo: ¿por qué crees que main "debe permanecer estable" y qué hiciste esta semana para lograrlo?
  2. Colaboración y respeto: describe el comentario de revisión que diste o recibiste. ¿Fue específico y constructivo?
  3. Orientación a la calidad: ¿qué parte de tu README todavía te falta completar en las próximas semanas?

Lista de cotejo (marca antes de entregar)

Rúbrica rápida (1 punto total)
Parte A: 0.15 · Parte B: 0.25 · Parte C: 0.30 · Parte D: 0.20 · Parte E: 0.10. Se valora que la rama, el README y la Pull Request existan de verdad en GitHub (se verifican los enlaces), que main se haya mantenido estable durante el proceso, y la honestidad de la reflexión.
