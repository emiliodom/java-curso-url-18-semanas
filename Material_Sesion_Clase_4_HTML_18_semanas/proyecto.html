Proyecto del curso · Semana 4 · Aplica lo aprendido a tu repositorio real

Crea la rama de desarrollo y documenta tu proyecto

Aquí aplicas, sobre tu repositorio real (el de la Guía 3), exactamente lo mismo que practicaste en Ejercicios: una rama, un README profesional y tu primera Pull Request.
Recordatorio: ¿qué estás construyendo?
Una aplicación web para el registro y gestión de una entidad sin fines de lucro (guardería, casa hogar o dispensario comunitario), construida de forma incremental durante las 18 semanas del curso. Con el tiempo incluirá: registro de beneficiarios, operaciones CRUD, autenticación por perfiles y roles, una interfaz amigable y responsiva, documentación técnica y despliegue en línea con HTTPS. Hoy le toca el turno a la organización con ramas y a la documentación (README).
¿Todavía no tienes tu repositorio de la Semana 3?
Este material asume que ya completaste la Guía 3: un repositorio publicado en GitHub con al menos un commit y un README inicial. Si te falta, complétalo primero — todo lo de esta página depende de tener ese repositorio real ya en línea.

Paso 1 — Verifica tu repositorio real

  1. Abre GitHub Desktop → botón "Current Repository" (arriba a la izquierda) → selecciona el repositorio de tu proyecto (el que publicaste en la Guía 3, no el de práctica de Ejercicios).
  2. Confirma que "Current Branch" muestre main y que no tengas cambios pendientes sin confirmar en "Changes".
✅ Checkpoint: ves el nombre correcto de tu proyecto en "Current Repository" y la rama activa es main.

Paso 2 — Crea la rama development

A partir de hoy, todo cambio nuevo del proyecto vive primero en esta rama — main se reserva para versiones ya revisadas y estables.

  1. Botón "Current Branch" → "New Branch".
  2. Nombre exacto: development (en minúsculas, sin espacios) → "Create Branch".
✅ Checkpoint: "Current Branch" ahora muestra development.

Paso 3 — Documenta tu README.md profesional

Dentro de development, actualiza el README.md real de tu proyecto con esta estructura mínima (plantilla completa en el cheat sheet, sección F):

  • Nombre del proyecto y una descripción breve de la entidad sin fines de lucro a la que atenderá.
  • Funcionalidades planeadas: registro de beneficiarios, CRUD, autenticación por roles, interfaz responsiva.
  • Tecnologías: Java, Spring Boot (a partir de la Semana 7).
  • Cómo clonar y ejecutar (aunque hoy sea un solo paso: "clonar este repositorio" — crecerá cada semana).
  • Autor: tu nombre.
  1. Repository → Open in Visual Studio Code, edita README.md con la estructura de arriba, guarda.
  2. GitHub Desktop → "Changes" → Summary: "Documenta el proyecto con README profesional" → "Commit to development".
✅ Checkpoint: tu commit aparece en la pestaña "History" de la rama development, no en main.

Paso 4 — Publica la rama y abre tu Pull Request

  1. Clic en "Publish branch".
  2. Menú Branch → Create Pull Request. Verifica: base: main ← compare: development.
  3. Título: "Rama de desarrollo: README profesional". Descripción: qué documentaste y por qué.
  4. Clic en "Create pull request". Copia el enlace — lo necesitarás en el Entregable.
✅ Checkpoint: tienes una Pull Request abierta y su enlace guardado.

Paso 5 — Pide (o simula) una revisión de código

La revisión entre pares es parte del valor de la semana: colaboración y respeto.

  • Si trabajas con un compañero: comparte el enlace de tu Pull Request y pide que deje al menos un comentario específico en "Files changed" antes de fusionar.
  • Si trabajas solo/a por ahora: repasa tu propio README con ojo crítico 24 horas después de escribirlo (o pide a alguien de tu familia que lo lea) y dejáte a ti mismo un comentario honesto de qué mejorarías — se acepta como evidencia de autorrevisión.
✅ Checkpoint: hay al menos un comentario de revisión (propio o de un compañero) en la Pull Request.

Paso 6 — Fusiona y sincroniza

  1. En la Pull Request (github.com): "Merge pull request" → "Confirm merge".
  2. En GitHub Desktop: "Current Branch" → main → clic en "Fetch origin".
  3. Confirma que el README de main ya muestra tu documentación profesional.
✅ Checkpoint: main tiene el README actualizado y la Pull Request aparece como "Merged".
Solución de problemas frecuentes
SituaciónQué hacer
No aparece el botón "New Branch"Confirma que estás dentro del repositorio correcto en "Current Repository" (no el de práctica de Ejercicios).
El commit apareció en main por errorDesde el historial, clic derecho sobre el commit → "Move to Branch..." → elige development.
La Pull Request muestra conflictosSigue exactamente los pasos de Cheat Sheet, sección E: editar el archivo, borrar las marcas y hacer "Commit merge".
No tengo con quién simular la revisiónUsa la opción de autorrevisión honesta del Paso 5, o pide a tu profesor/a que deje el comentario.
Plan B (si algo falla técnicamente)
Si GitHub Desktop no permite crear la Pull Request: crea la rama development y edita el README directo en la interfaz web de GitHub (botón "Edit this file" estando en esa rama), luego abre la Pull Request desde ahí — el resultado final es el mismo.
