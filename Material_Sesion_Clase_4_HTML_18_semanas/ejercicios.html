Guía de ejercicios · Semana 4 · Con GitHub Desktop

De la rama a la Pull Request, paso a paso

Practicarás con un repositorio nuevo de bajo riesgo — el catálogo de una tienda de artículos deportivos ficticia — antes de aplicar lo mismo a tu proyecto real en la sección Proyecto.
¿Por qué un repositorio aparte para practicar?
Vas a provocar un conflicto de fusión a propósito (Ejercicio 8) — mejor practicarlo aquí que en el repositorio real de tu proyecto. Cuando domines el flujo, repítelo con tu proyecto en Proyecto.
Plan B — si necesitas repasar GitHub Desktop
Revisa la instalación y lo básico de commits en Instala GitHub Desktop — Semana 3, o practica el concepto de ramas en Learn Git Branching (simulador en el navegador).

Ejercicio 1 — Crea el repositorio de práctica Calentamiento

Objetivo: tener un repositorio nuevo, de bajo riesgo, para practicar ramas.

  1. File → New Repository...
  2. Name: tienda-deportes-practica.
  3. Marca "Initialize this repository with a README" y elige Git ignore: Java.
  4. Clic en "Create repository" y luego en "Publish repository" (público).
¿Qué deberías ver?
Tu repositorio en github.com/tu-usuario/tienda-deportes-practica, con un README.md inicial y la rama activa mostrando main en el botón "Current Branch".

Ejercicio 2 — Crea tu primera rama New Branch

Objetivo: crear una rama para agregar el catálogo de productos, sin tocar main.

  1. Clic en el botón "Current Branch" (arriba).
  2. Clic en "New Branch", escribe feature-catalogo → "Create Branch".
  3. Confirma que "Current Branch" ahora muestra feature-catalogo.
¿Qué deberías ver?
GitHub Desktop te movió automáticamente a la nueva rama. Todavía es idéntica a main — no hay diferencias hasta que edites algo.

Ejercicio 3 — Trabaja en tu rama Changes + Commit

Objetivo: hacer un cambio real dentro de la rama y confirmarlo con un commit.

  1. Menú Repository → Open in Visual Studio Code.
  2. En README.md, agrega una sección: ## Catálogo de productos con 3 productos de ejemplo (ej. balón, camiseta, tenis).
  3. Guarda (Ctrl + S) y vuelve a GitHub Desktop → pestaña "Changes".
  4. Summary: "Agrega sección de catálogo" → "Commit to feature-catalogo".
¿Qué deberías ver?
El botón de commit dice "Commit to feature-catalogo", no "main" — confirma que el cambio vive solo en tu rama.

Ejercicio 4 — Publica la rama Publish branch

Objetivo: subir tu rama nueva a GitHub (todavía separada de main).

  1. Con el commit ya hecho, busca el botón "Publish branch" arriba.
  2. Clic — GitHub Desktop sube la rama feature-catalogo tal cual, sin tocar main en GitHub.
  3. Menú Repository → View on GitHub: cambia el selector de ramas y confirma que feature-catalogo ya existe en línea.
¿Qué deberías ver?
En github.com aparece un botón amarillo "Compare & pull request" — GitHub detectó que subiste una rama nueva y sugiere el siguiente paso.

Ejercicio 5 — Abre una Pull Request Pull Request

Objetivo: proponer formalmente que feature-catalogo se integre a main.

  1. En GitHub Desktop: menú Branch → Create Pull Request (o el botón "Compare & pull request" en github.com).
  2. Verifica: base: main ← compare: feature-catalogo.
  3. Título: "Agrega catálogo de productos". Descripción: qué agregaste y por qué.
  4. Clic en "Create pull request".
¿Qué deberías ver?
Una página de Pull Request con tu título, descripción, y la pestaña "Files changed" mostrando exactamente la línea que agregaste al README, resaltada en verde.

Ejercicio 6 — Revisa el código Revisión

Objetivo: practicar dar retroalimentación de código de forma respetuosa y específica.

  1. En la pestaña "Files changed" de tu propia Pull Request, coloca el cursor sobre la línea que agregaste.
  2. Clic en el ícono "+" que aparece a la izquierda de la línea para dejar un comentario.
  3. Escribe un comentario constructivo, como si fueras un compañero revisando (ej. "¿Agregarías también el precio de cada producto?").
Pista
Un buen comentario de revisión describe qué mejorarías y por qué — nunca solo "está mal" o "no me gusta".

Ejercicio 7 — Fusiona y sincroniza Merge

Objetivo: integrar tu rama a main y traer el cambio de vuelta a tu computadora.

  1. En la Pull Request (github.com): clic en "Merge pull request" → "Confirm merge".
  2. En GitHub Desktop: "Current Branch" → selecciona main → clic en "Fetch origin".
  3. Confirma que tu README en main ya tiene la sección de catálogo.
  4. (Opcional) borra feature-catalogo: clic derecho sobre ella en "Current Branch" → "Delete".
¿Qué deberías ver?
El README de main (no solo el de la rama) ya incluye tu sección de catálogo. La Pull Request en GitHub aparece marcada como "Merged" en morado.

Ejercicio 8 — Reto integrador: provoca y resuelve un conflicto Integrador

Objetivo: vivir un conflicto de fusión real y resolverlo con calma.

  1. Desde main actualizada, crea dos ramas nuevas: feature-precios y feature-descuentos.
  2. En ambas, edita la misma línea del README (ej. la línea del balón) con textos distintos, y haz commit en cada una por separado.
  3. Publica y fusiona primero feature-precios a main (sin conflicto, es la primera).
  4. Publica feature-descuentos e intenta fusionarla: aparecerá un conflicto porque esa línea ya cambió en main.
  5. Abre el archivo en conflicto en VS Code, decide qué texto conservar, borra las marcas <<<<<<< / ======= / >>>>>>>, guarda y confirma el "Commit merge" en GitHub Desktop.
¿Qué deberías ver al terminar?
main con la línea final que tú decidiste conservar (o combinar), sin ninguna marca de conflicto visible en el archivo. Este es exactamente el flujo que puede aparecer en tu proyecto real cuando trabajes en equipo.
¿Terminaste todo?
Pasa al Challenge "Ordena el flujo de colaboración" en nivel Difícil, o aplica exactamente este flujo a tu proyecto real en Proyecto. Antes de pedir ayuda: relee el mensaje en pantalla, consulta el cheat sheet e intenta de nuevo.
