¿Qué aprendiste hoy?

10 preguntas sobre ramas, Pull Requests, merges, conflictos y documentación. Al terminar: Calificar → Exportar a PDF → subir al aula virtual.
1) ¿Qué es una rama (branch) en Git?
✅ Correcto: te deja experimentar mientras main permanece estable.
Es una copia paralela del proyecto. Permite experimentar sin arriesgar la versión estable en main.
2) ¿Cuál botón de GitHub Desktop crea una rama nueva y te mueve a ella?
✅ Correcto: crea la rama y te mueve a ella en un solo paso.
Es "Current Branch" → "New Branch". Las otras opciones no crean ramas.
3) ¿Qué es una Pull Request?
✅ Correcto: propone la fusión y permite que alguien revise el código antes.
Es una propuesta de fusión con espacio para revisión — no borra nada ni guarda contraseñas.
4) En una Pull Request, ¿qué significa "base: main ← compare: feature-x"?
✅ Correcto: los cambios van HACIA main, no al revés.
Significa que los cambios de feature-x se proponen para integrarse a main.
5) ¿Cuál de estos comentarios de revisión de código es constructivo?
✅ Correcto: explica qué revisar y por qué, de forma respetuosa.
Es la opción C: específica, respetuosa y explica el motivo. Las otras no ayudan a mejorar el código.
6) ¿Cuándo aparece un conflicto de fusión (merge conflict)?
✅ Correcto: Git no puede decidir solo cuál versión conservar y pide que una persona lo resuelva.
Aparece cuando dos ramas cambian la misma línea. Es normal, no un error.
7) Al resolver un conflicto, ¿qué se debe hacer con las marcas <<<<<<<, ======= y >>>>>>>?
✅ Correcto: deben desaparecer del archivo por completo antes de confirmar el "Commit merge".
Deben borrarse por completo. Si quedan, el archivo tendrá texto inválido mezclado con el código real.
8) ¿Qué comando de terminal crea una rama nueva y te mueve a ella en un solo paso (equivalente a "New Branch")?
✅ Correcto (o su forma moderna git switch -c). git branch sola solo la crea, sin moverte a ella.
Es git checkout -b nueva-rama (o git switch -c nueva-rama).
9) ¿Qué debería tener, como mínimo, un README.md profesional del proyecto del curso?
✅ Correcto: esa estructura mínima ya responde qué es el proyecto, para qué sirve y quién lo hizo.
Debe incluir nombre, descripción, funcionalidades, tecnologías y autor. Nunca contraseñas ni datos sensibles.
10) Terminaste de fusionar tu Pull Request. ¿Qué falta para que tu computadora refleje el cambio?
✅ Correcto: "Fetch origin" trae los cambios recién fusionados a tu copia local.
Falta cambiar a main y hacer "Fetch origin" para traer el cambio a tu computadora.
