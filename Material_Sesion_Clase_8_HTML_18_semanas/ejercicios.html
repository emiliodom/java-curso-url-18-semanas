Guía de ejercicios · Semana 8 · 100% en tu propia computadora

Tu primer servicio REST, de verdad, corriendo en tu máquina

Estos 7 ejercicios se hacen en tu proyecto de práctica laboratorio-spring (el mismo de la Semana 7, o uno nuevo con la dependencia Spring Web). Dominio de ejemplo: Comedor Solidario Manos Unidas. Cada uno tiene una pista, un checkpoint y una solución en <details> por si te atoras.
Antes de empezar: la pregunta ancla de esta semana
En cada ejercicio pregúntate: ¿la URL que escribí coincide EXACTAMENTE con el texto dentro de @GetMapping("...")? Java (y las rutas web) distinguen mayúsculas de minúsculas.

Ejercicio 1 — Confirma que tu proyecto sigue vivo Calentamiento

Abre tu proyecto laboratorio-spring de la Semana 7 (o genera uno nuevo con Spring Web) y ejecútalo.

Tu turno: ¿qué ves en localhost:8080 ahora mismo, antes de tocar nada hoy?

Solución
La Whitelabel Error Page (404) — es lo esperado, todavía no existe ningún @RestController en el proyecto. Eso cambia en el Ejercicio 2.

Ejercicio 2 — Tu primer @RestController Real

Crea una clase SaludoController.java junto a tu clase ...Application.java:

@RestController
public class SaludoController {

    @GetMapping("/api/saludo")
    public String saludo() {
        return "¡Bienvenido(a) al Comedor Solidario Manos Unidas!";
    }
}

Tu turno: reinicia el proyecto y visita localhost:8080/api/saludo. ¿Qué ves?

Solución
El texto exacto que devuelve el método: "¡Bienvenido(a) al Comedor Solidario Manos Unidas!" — sin comillas, como texto plano en la página. Ya no aparece la Whitelabel Error Page.

Ejercicio 3 — Endpoint con parámetro Real

En la misma clase, agrega un segundo método:

@GetMapping("/api/bienvenida")
public String bienvenida(@RequestParam(defaultValue = "visitante") String nombre) {
    return "Hola, " + nombre + ". Gracias por apoyar al Comedor Solidario Manos Unidas.";
}

Tu turno: visita /api/bienvenida (sin parámetro) y luego /api/bienvenida?nombre=Carla. ¿Qué cambia?

Solución
Sin parámetro, usa el valor por defecto "visitante". Con ?nombre=Carla, el mensaje dice "Hola, Carla...". @RequestParam lee lo que va después del ? en la URL.

Ejercicio 4 — Pruébalo con Postman (o Thunder Client) Herramienta

Crea una petición GET a http://localhost:8080/api/bienvenida?nombre=Luis en Postman o en la extensión "Thunder Client" de VS Code.

Tu turno: además del texto de respuesta, ¿qué otra información ves que el navegador normalmente no te muestra tan claro?

Solución
El código de estado (200 OK), los headers de la respuesta (ej. Content-Type) y el tiempo que tardó la petición. Esto será clave más adelante, cuando trabajes con rutas POST que Postman puede probar y el navegador no.

Ejercicio 5 — Tu primer formulario web Real

Crea src/main/resources/static/index.html con un formulario y JavaScript que llame a /api/bienvenida con fetch (ver el código completo en el Cheat Sheet, sección A).

Tu turno: reinicia el proyecto, visita localhost:8080 (sin ninguna ruta) y prueba el formulario. ¿Se recarga la página al enviarlo?

Solución
No se recarga — e.preventDefault() lo evita, y fetch hace la petición en segundo plano. El mensaje de respuesta aparece dentro de <p id="resultado">.

Ejercicio 6 — Provoca un error de ruta Interpretar

Visita a propósito localhost:8080/api/Bienvenida (con mayúscula) o localhost:8080/api/bienvenidaa (con una letra de más).

Tu turno: ¿qué página aparece y por qué, aunque tu código esté correcto?

Solución
Vuelve a aparecer la Whitelabel Error Page (404): Spring Boot busca una ruta EXACTA a lo escrito en @GetMapping. Un solo carácter distinto ya no coincide — es el error más común de la semana.

Ejercicio 7 — Reto integrador: un tercer endpoint + commit Integrador

Agrega un tercer método @GetMapping("/api/menu-del-dia") que devuelva el nombre de un platillo cualquiera (inventado). Prueba las 3 rutas. Sube el proyecto de práctica a un repositorio de GitHub (o commitea si ya lo tenías ahí) con el mensaje "Agrega SaludoController y formulario web".

Tu turno: ¿por qué es buena práctica comitear ahora, en vez de esperar a tener 10 endpoints?

Ejemplo de solución
Commits pequeños y frecuentes son más fáciles de revisar, de revertir si algo sale mal, y muestran el progreso real del trabajo — el mismo hábito que practicaste en las Semanas 3–4 con ramas y Pull Requests.
