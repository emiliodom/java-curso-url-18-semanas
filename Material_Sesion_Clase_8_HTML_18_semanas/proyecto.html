Tu primer endpoint y formulario, reales, en tu proyecto

Esta página tiene dos partes: primero una guía paso a paso para agregar un @RestController y un formulario web a tu proyecto real, y al final la plantilla calificable que debes completar y entregar. Fecha límite: antes de la Sesión 9 (5 de septiembre de 2026). Esta semana no tiene Entrega Parcial adicional — el siguiente hito es la Entrega Parcial 2, en la Semana 9.
Antes de empezar
Necesitas: el proyecto Spring Boot que generaste y subiste a GitHub en la Semana 7, corriendo en tu máquina, y tu Ficha del Proyecto (nombre de la entidad/institución) a la mano. Hoy no se guarda ningún dato — solo consultas (GET). El guardado real llega más adelante en el curso.

Parte guiada — agrega tu primer servicio real

Paso 1 — Abre tu proyecto real de la Semana 7

Abre en VS Code la carpeta de tu proyecto Spring Boot real (el que generaste con el Group/Artifact de tu institución) y ejecútalo para confirmar que sigue arrancando.

✅ Checkpoint: en la terminal aparece "Started ... Application in X seconds" y localhost:8080 sigue mostrando la Whitelabel Error Page (todavía no hay rutas).

Paso 2 — Crea tu @RestController con datos reales de tu proyecto

Crea una clase controladora (ej. BienvenidaController.java) junto a tu clase Application.java, usando el nombre real de tu entidad/institución:

@RestController
public class BienvenidaController {

    @GetMapping("/api/saludo")
    public String saludo() {
        return "¡Bienvenido(a) a Guardería Esperanza!"; // usa el nombre real de tu institución
    }

    @GetMapping("/api/bienvenida")
    public String bienvenida(@RequestParam(defaultValue = "visitante") String nombre) {
        return "Hola, " + nombre + ". Gracias por visitar Guardería Esperanza.";
    }
}
✅ Checkpoint: reiniciaste el proyecto y ambas rutas responden en el navegador con texto relacionado a tu institución real (no con datos de ejemplo genéricos).

Paso 3 — Pruébalo con Postman o Thunder Client

Crea una petición GET a tu ruta /api/bienvenida?nombre=... en Postman (o la extensión "Thunder Client" de VS Code) y confirma el código de estado 200 OK.

✅ Checkpoint: viste la respuesta correcta y el código 200 OK en Postman/Thunder Client, además del navegador.

Paso 4 — Construye tu formulario web

Crea src/main/resources/static/index.html con un formulario y JavaScript (fetch) que llame a tu endpoint (código completo en el Cheat Sheet, sección A) — cambia los textos por el nombre real de tu institución.

✅ Checkpoint: al visitar localhost:8080, aparece tu formulario; al escribir un nombre y enviarlo, el mensaje aparece sin recargar la página.

Paso 5 — Sube los cambios a tu repositorio real

En GitHub Desktop, dentro de tu rama development: confirma el cambio ("Commit to development") con el resumen "Agrega BienvenidaController y formulario web", y publica/sincroniza la rama.

✅ Checkpoint: tu rama development en GitHub.com muestra tu nueva clase controladora y el archivo static/index.html.
Solución de problemas frecuentes
SituaciónQué hacer
Whitelabel Error Page al visitar mi propia rutaCompara letra por letra con @GetMapping("...") (mayúsculas incluidas) y reinicia el proyecto tras cada cambio.
El formulario no muestra ningún mensajeRevisa la consola del navegador (F12) — casi siempre es un error de sintaxis en el JavaScript o una ruta mal escrita en el fetch.
"Port 8080 was already in use"Ya tienes otra copia corriendo (tal vez del proyecto de práctica). Deténla o usa otro puerto temporalmente con server.port.
GitHub Desktop no detecta los archivos nuevosVerifica que BienvenidaController.java y static/index.html están DENTRO de la carpeta de tu repositorio local.
