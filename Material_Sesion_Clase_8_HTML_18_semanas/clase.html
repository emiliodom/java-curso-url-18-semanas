Abre pom.xml y ubica la dependencia agregada la semana pasada:

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
Qué es un "Starter"
Un Starter es un paquete de dependencias ya combinadas para un propósito (aquí, "construir aplicaciones web"). spring-boot-starter-web trae, entre otras cosas, Tomcat embebido y todo lo necesario para escribir controladores REST — es la misma pieza que ya tenías desde el Paso 2 de Spring Initializr en la Semana 7, sin agregar nada nuevo hoy.

Elevator pitch de @RestController: en la arquitectura en capas (Semanas 5–6), es la anotación que marca una clase como parte de la capa de presentación/controlador — recibe peticiones HTTP y devuelve una respuesta (texto, JSON, etc.) directamente, sin pasar por una vista HTML como haría un controlador MVC tradicional con Thymeleaf.

Conexión con la Semana 6 (antipatrón de saltarse capas)
Hoy, por simplicidad, el controlador va a construir la respuesta directamente. En proyectos reales, un controlador NO debería contener lógica de negocio pesada — eso vive en la capa de Servicio. Lo veremos formalmente cuando el proyecto crezca; hoy el controlador es simple a propósito.

Dentro de src/main/java/.../, junto a la clase ...Application.java, crea una nueva clase BienvenidaController.java (dominio de ejemplo: Comedor Solidario Manos Unidas):

package gt.edu.url.laboratoriospring;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class BienvenidaController {

    @GetMapping("/api/saludo")
    public String saludo() {
        return "¡Bienvenido(a) al Comedor Solidario Manos Unidas!";
    }

    @GetMapping("/api/bienvenida")
    public String bienvenida(@RequestParam(defaultValue = "visitante") String nombre) {
        return "Hola, " + nombre + ". Gracias por apoyar al Comedor Solidario Manos Unidas.";
    }
}
PiezaQué hace
@RestControllerMarca la clase completa como un controlador que responde directamente con datos (texto/JSON), no con una vista.
@GetMapping("/api/saludo")Conecta la ruta /api/saludo con este método, solo para peticiones GET.
@RequestParam(defaultValue = "visitante")Lee un parámetro de la URL (ej. ?nombre=Ana); si no viene, usa el valor por defecto — así el endpoint no falla si lo visitas sin parámetro.

Guarda, reinicia el proyecto (⏹ y ▶ Run de nuevo) y confirma en el log que sigue arrancando sin errores.

En el navegador, visita:

http://localhost:8080/api/saludo
http://localhost:8080/api/bienvenida
http://localhost:8080/api/bienvenida?nombre=Marta

Ya no aparece la Whitelabel Error Page — el navegador muestra el texto que devolvió el método. La Semana 7 terminó aquí; hoy ya llegamos más lejos.

Ahora la misma prueba con Postman (o la extensión "Thunder Client" de VS Code, más liviana): crea una petición GET a http://localhost:8080/api/bienvenida?nombre=Marta y muestra el resultado, resaltando que también se ven los headers de la respuesta.

¿Por qué usar Postman si el navegador ya funciona?
Para rutas GET simples como las de hoy, el navegador es suficiente. Postman se vuelve indispensable más adelante en el curso, cuando existan rutas POST/PUT que envían datos en el cuerpo de la petición (no en la URL) — algo que un navegador no puede hacer con solo escribir una dirección.

Spring Boot sirve automáticamente cualquier archivo dentro de src/main/resources/static/. Crea ahí un archivo index.html:

<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8" />
  <title>Comedor Solidario Manos Unidas</title>
</head>
<body>
  <h1>Comedor Solidario Manos Unidas</h1>
  <form id="formBienvenida">
    <label for="nombre">Tu nombre:</label>
    <input type="text" id="nombre" name="nombre" required />
    <button type="submit">Enviar saludo</button>
  </form>
  <p id="resultado"></p>

  <script>
    document.getElementById('formBienvenida').addEventListener('submit', function (e) {
      e.preventDefault();
      var nombre = document.getElementById('nombre').value;
      fetch('/api/bienvenida?nombre=' + encodeURIComponent(nombre))
        .then(function (respuesta) { return respuesta.text(); })
        .then(function (texto) { document.getElementById('resultado').textContent = texto; });
    });
  </script>
</body>
</html>
Pieza del JavaScriptQué hace
e.preventDefault()Evita que el formulario recargue la página al enviarse — así la respuesta aparece sin perder el contexto.
fetch('/api/bienvenida?nombre=...')Hace, en JavaScript, la misma petición GET que hicimos a mano en el navegador y en Postman.
.then(...text())Lee la respuesta como texto plano (el método del controlador devuelve un String, no JSON).

Reinicia el proyecto y visita http://localhost:8080 (sin ninguna ruta después) — Spring Boot muestra automáticamente ese index.html. Escribe un nombre, pulsa "Enviar saludo" y observa el mensaje aparecer sin recargar la página.

Esto NO es Thymeleaf
index.html es un archivo estático común y corriente; el navegador lo descarga tal cual y JavaScript hace el resto. Thymeleaf (Semana 10) permitirá que el propio servidor genere HTML dinámico con datos de Java — una forma distinta y más potente de construir vistas.
