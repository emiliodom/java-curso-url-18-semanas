Banco de Preguntas del Tribunal Evaluador

Durante tu defensa de 4 minutos, el docente formulará una o dos preguntas técnicas para validar tu autoría y comprensión de la arquitectura. Estudia estas 8 preguntas clave con sus respuestas modelo.

Arquitectura

1. ¿Por qué dividiste tu proyecto en capas (MVC) en lugar de escribir todo en el Controlador?

Qué evalúa el profesor: Principio de responsabilidad única y bajo acoplamiento.

Ver respuesta modelo recomendada
«Separamos en capas para cumplir el principio de responsabilidad única. El Controlador solo atiende el tráfico HTTP y delega la lógica al Servicio y el acceso a datos al Repositorio. Si en el futuro cambiamos la base de datos de Neon a otra plataforma, solo modificamos la configuración o el repositorio sin romper la interfaz gráfica de Thymeleaf.»
Spring Web

2. ¿Qué diferencia hay entre @Controller y @RestController, y por qué usaste @Controller?

Qué evalúa el profesor: Renderizado de vistas HTML vs entrega de JSON crudo.

Ver respuesta modelo recomendada
«@RestController devuelve directamente datos en formato JSON o texto crudo al cuerpo de la respuesta (usado en APIs). En cambio, @Controller devuelve el nombre de una plantilla HTML (como return "formulario";) para que el motor Thymeleaf la procese y renderice la interfaz web completa para el usuario final.»
Persistencia y Nube

3. ¿Por qué la base de datos PostgreSQL vive en Neon y no en la base gratuita de Render?

Qué evalúa el profesor: Comprensión operativa de la persistencia y perfiles de nube.

Ver respuesta modelo recomendada
«Porque la base de datos gratuita de Render expira a los 30 días y borra la información. Neon, en cambio, ofrece un nivel gratuito sin fecha de caducidad; solo suspende el cómputo por inactividad y se reactiva automáticamente con la primera consulta JDBC, asegurando que los datos de la institución nunca se pierdan.»
Validación y UX

4. Cuando un usuario envía un formulario con errores, ¿por qué NO se debe usar return "redirect:..."?

Qué evalúa el profesor: Ciclo de peticiones HTTP, estado y retención de datos.

Ver respuesta modelo recomendada
«Porque una redirección (HTTP 302) le ordena al navegador solicitar una nueva página GET limpia, lo que destruye el objeto de error inyectado en BindingResult y borra todo lo que el usuario había escrito. Al devolver la plantilla directamente (return "formulario"), Thymeleaf conserva los campos y resalta los errores en rojo.»
Patrón PRG

5. ¿Cuál es el beneficio de aplicar el patrón POST-Redirect-GET tras guardar con éxito?

Qué evalúa el profesor: Prevención de duplicación de registros por refresco (F5).

Ver respuesta modelo recomendada
«Evita que el usuario duplique registros si presiona F5 o el botón de refrescar. Al redirigir tras el POST exitoso, el navegador queda en una petición GET segura; si el usuario refresca, simplemente vuelve a consultar la lista sin reenviar el formulario a la base de datos.»
Seguridad e Higiene

6. ¿Por qué es un error grave de seguridad escribir contraseñas en application.properties?

Qué evalúa el profesor: Manejo de secretos y separación de configuración (12-Factor App).

Ver respuesta modelo recomendada
«Porque ese archivo se sube a GitHub en el control de versiones público. Si quemamos contraseñas allí, cualquier persona o bot malicioso puede leer la clave y vulnerar la base de datos de Neon. La buena práctica exige usar variables de entorno configuradas en el dashboard de Render (como ${DB_PASSWORD}).»
Thymeleaf

7. ¿Cómo sabe Spring Boot qué datos mostrar en la tabla de lista.html?

Qué evalúa el profesor: Vinculación entre el Model de Spring y la expresión th:each.

Ver respuesta modelo recomendada
«El controlador consulta repositorio.findAll() y lo agrega al objeto Model con model.addAttribute("beneficiarios", lista). Luego, Thymeleaf en el HTML itera sobre esa colección usando th:each="item : ${beneficiarios}" y dibuja una fila <tr> por cada registro recuperado.»
DevOps y CI/CD

8. ¿Qué ventaja ofrece el Dockerfile multietapa al desplegar en Render?

Qué evalúa el profesor: Optimización de contenedores y tamaño de imagen en producción.

Ver respuesta modelo recomendada
«La primera etapa descarga Maven y el JDK completo para compilar el .jar. La segunda etapa copia únicamente el archivo compilado sobre una imagen JRE liviana de Eclipse Temurin 17. Esto reduce el tamaño de la imagen, acelera el arranque en Render y disminuye la superficie de vulnerabilidades en producción.»
