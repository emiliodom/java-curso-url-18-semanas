"12-factor app" en tres reglas simples

Es una lista famosa de buenas prácticas para aplicaciones en internet. Para este curso bastan tres:

1 · Un código, muchos lugares

El mismo repositorio sirve para tu PC y para producción. No hay "una copia especial para el servidor".

2 · La configuración vive afuera

Lo que cambia entre lugares (dónde está la base, las claves, el puerto) llega por variables de entorno, nunca escrito en el código.

3 · Los datos viven en un servicio aparte

El disco del servidor es desechable (Render lo borra en cada despliegue). Lo que debe durar va a Neon.

Si una clave llega a GitHub o a un log
Primero cámbiala (Neon → Roles → Reset password) y actualízala en Render; después limpia el archivo. Borrar la línea no basta: el historial de un repositorio público la conserva.
