¿Qué aprendiste hoy?

10 preguntas sobre Git y GitHub. Al terminar: Calificar → Exportar a PDF → subir al aula virtual.
1) ¿Qué comando crea un repositorio de Git en la carpeta actual?
✅ git init crea el repositorio, una sola vez por proyecto.
Es git init. Se ejecuta una sola vez, al comenzar el proyecto.
2) Un archivo nuevo aparece en rojo al hacer git status. ¿Qué significa?
✅ Correcto: falta git add para que pase al área de preparación.
Significa "untracked" (sin seguimiento). Necesitas git add antes de poder incluirlo en un commit.
3) ¿Qué hace exactamente git add archivo.txt?
✅ Correcto: prepara el archivo para el próximo git commit; no sube nada a internet todavía.
Solo lo prepara para el commit (staging). Para subir a internet hace falta después git push.
4) ¿Cuál es el mejor mensaje de commit?
✅ Correcto: describe con claridad qué cambia, en presente.
Es la opción B: un mensaje claro dice qué cambia. "cambios" o "asdf" no ayudan a nadie después.
5) ¿Qué comando conecta tu repositorio local con uno en GitHub?
✅ Correcto: remote add conecta tu carpeta local con la dirección remota.
Es git remote add origin URL. "origin" es solo el apodo más común para esa dirección remota.
6) ¿Para qué sirve el -u en git push -u origin main?
✅ Correcto: después de usarlo una vez, basta con git push a secas.
Recuerda la conexión (upstream) entre tu rama local y la remota, para simplificar los próximos push.
7) ¿Qué archivo le dice a Git qué NO debe vigilar?
✅ Correcto: .gitignore lista patrones de archivos que Git debe ignorar.
Es .gitignore. Sirve para que archivos como carpetas generadas o datos sensibles nunca se suban.
8) ¿Cuál es la diferencia entre Git y GitHub?
✅ Correcto: uno es la herramienta local, el otro el servicio en internet.
Git es local (tu terminal); GitHub es remoto (un sitio web que aloja tu repositorio y permite colaborar).
9) Intentas git push y aparece failed to push some refs (rejected). ¿Qué es lo primero que intentas?
✅ Correcto: el remoto tiene algo que tu copia local no tiene; git pull lo trae antes de reintentar.
Lo correcto es git pull primero: sincroniza tu copia local con lo que ya existe en el remoto.
10) ¿Qué comando crea una rama nueva y te mueve a ella en un solo paso?
✅ Correcto (o su forma moderna git switch -c). git branch sola solo la crea, sin moverte a ella.
Es git checkout -b nueva-rama (o git switch -c nueva-rama). Verás esto a fondo la próxima semana.
