Entregable · Guía de Aprendizaje 3 · Trabajo autónomo (1 pt)

Repositorio inicial del proyecto en GitHub

Completa esta plantilla durante la semana y súbela antes de la Sesión 4 (1 de agosto de 2026). Llena los campos, luego Exportar a PDF y súbelo al aula virtual como Guia3_TuNombre.pdf.

Datos del estudiante

Instrucciones generales
  1. Este entregable es el inicio real del repositorio de tu proyecto (la app para tu entidad sin fines de lucro): lo seguirás usando toda la carrera.
  2. Trabaja con GitHub Desktop (ver cheat sheet si te trabas) o, si ya te sientes cómoda con comandos, directo en la terminal (ver Anexo: Comandos) — ambos caminos son válidos.
  3. El dato más importante que debes entregar es el enlace público a tu repositorio en GitHub (Parte C).
  4. Trabaja con autonomía: antes de preguntar, relee el mensaje en pantalla, consulta el cheat sheet e intenta de nuevo.
¿Usaste comandos en vez de GitHub Desktop?
Perfecto, esta guía acepta ambos caminos. En cada campo que pide una acción de GitHub Desktop, escribe en su lugar el comando equivalente que usaste (ej. git commit -m "..." en vez de "Commit to main", git push en vez de "Publish repository" — ver el Anexo: Comandos). Lo que se califica es que tu repositorio, tu README y tu historial de commits existan de verdad en GitHub — no la herramienta que usaste para lograrlo.

Parte A — Verificación de entorno (15%)

Confirma que GitHub Desktop tiene sesión iniciada y tu identidad configurada.

Parte B — Primer commit local (30%)

En GitHub Desktop: File → New Repository... con el nombre real de tu proyecto. Edita el README.md desde VS Code con: nombre del proyecto, una frase describiendo la entidad sin fines de lucro que atenderá, y tu nombre como autor. Guarda y haz tu primer commit ("Changes" → Summary → "Commit to main").

Parte C — Repositorio remoto en GitHub (35%)

Clic en "Publish repository", confirma que el repositorio quede público y sube tu proyecto.

Parte D — Buenas prácticas: .gitignore (10%)

Si elegiste "Git ignore: Java" al crear el repositorio (Parte B), GitHub Desktop ya generó este archivo por ti — solo revísalo y complétalo si hace falta (puedes basarte en el del cheat sheet).

Parte E — Reflexión (10%)

  1. Orden y trazabilidad: copia uno de tus mensajes de commit y explica por qué es (o no es) claro para alguien que lo lea dentro de 6 meses.
  2. Seguridad colaborativa: ¿cómo te protege Git ante la posibilidad de perder tu progreso o dañar tu computadora?
  3. Proactividad: ¿qué dificultad tuviste esta semana y qué hiciste antes de pedir ayuda?
