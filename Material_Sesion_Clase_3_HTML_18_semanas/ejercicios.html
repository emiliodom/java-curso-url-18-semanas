Guía de ejercicios · Semana 3 · Con GitHub Desktop

Tu primer repositorio, paso a paso

Estos ejercicios se hacen con GitHub Desktop (sin escribir comandos). Si aún no lo tienes instalado, ve primero a Instala GitHub Desktop.
¿Ya sabes usar comandos y prefieres la terminal?
Perfecto — todo lo de esta página tiene su equivalente exacto en comandos en el Anexo: Comandos. Resuelve los mismos 8 ejercicios ahí, con git directamente.
Plan B — si ni siquiera puedes instalar GitHub Desktop hoy
Practica el concepto en Learn Git Branching (simulador en el navegador) o crea/edita archivos directo en la interfaz web de GitHub (botón "Add file", sin instalar nada) mientras instalas GitHub Desktop durante la semana.

Ejercicio 1 — Verifica tu cuenta y tu identidad Calentamiento

Objetivo: confirmar que GitHub Desktop tiene sesión iniciada y tu identidad configurada.

  1. Abre GitHub Desktop.
  2. Mira arriba a la derecha: ¿aparece tu nombre de usuario de GitHub?
  3. Ve a File → Options (Windows) o GitHub Desktop → Preferences (Mac) → pestaña Git. Confirma tu Name y Email.
¿Qué deberías ver?
Tu usuario visible arriba a la derecha, y en la pestaña "Git" de Options/Preferences, tu nombre real y el mismo correo que usarás para el proyecto del curso. Si falta algo, repite el Paso 5 de la guía de instalación.

Ejercicio 2 — Crea tu primer repositorio New Repository

Objetivo: crear tu primer repositorio local y observar qué trae de fábrica.

  1. Menú File → New Repository...
  2. Name: practica-git.
  3. Marca "Initialize this repository with a README".
  4. En Git ignore, elige "Java" del desplegable.
  5. Clic en "Create repository".
¿Qué deberías ver?
La pantalla principal del repositorio, con un archivo README.md y un archivo .gitignore ya listados, y el botón "Publish repository" arriba. Esto es el equivalente visual de git init.

Ejercicio 3 — Tu primer commit Changes + Commit

Objetivo: editar un archivo y guardar una "fotografía" del cambio.

  1. Menú Repository → Open in Visual Studio Code.
  2. Abre README.md, agrega una línea de texto y guarda (Ctrl + S).
  3. Vuelve a GitHub Desktop → pestaña "Changes": ¿de qué color aparece el cambio en la vista previa?
  4. Escribe un mensaje en "Summary" y clic en "Commit to main".
¿Qué deberías ver?
En "Changes", la línea agregada aparece resaltada en verde. Tras el commit, la pestaña "History" muestra tu commit con el mensaje que escribiste.

Ejercicio 4 — Ignorar archivos con .gitignore .gitignore

Objetivo: evitar que Git vigile un archivo que no debe compartirse.

  1. Desde VS Code, crea un archivo notas_personales.txt (simula un archivo que no quieres compartir).
  2. Vuelve a GitHub Desktop → pestaña "Changes": debería aparecer listado.
  3. Abre el archivo .gitignore (ya existe, del Ejercicio 2) y agrega una línea: notas_personales.txt.
  4. Vuelve a "Changes": ¿sigue apareciendo notas_personales.txt?
¿Qué deberías ver?
Después de agregarlo a .gitignore, notas_personales.txt desaparece de la pestaña "Changes" — GitHub Desktop ya no lo "ve". Sí verás el cambio del propio .gitignore listado (ese sí hay que hacerle commit).

Ejercicio 5 — Publica tu repositorio en GitHub Publish

Objetivo: crear la copia remota en GitHub y subir tu historial, en un solo paso.

  1. Arriba, clic en el botón "Publish repository".
  2. Confirma el nombre. Desmarca "Keep this code private" si quieres que sea público (recomendado para este curso).
  3. Clic en "Publish Repository".
¿Qué deberías ver?
El botón "Publish repository" cambia a "Fetch origin". Este único clic hizo, por debajo, lo mismo que crear un repositorio vacío en GitHub, conectarlo y subir tu historial completo por primera vez.

Ejercicio 6 — Verifica en GitHub.com Verificación

Objetivo: confirmar que tu repositorio existe de verdad en internet.

  1. Menú Repository → View on GitHub.
  2. Confirma que tu README.md y tu commit aparecen ahí.
  3. Copia la URL de tu repositorio — la necesitarás para el Entregable.
Pista
La URL se ve así: https://github.com/tu-usuario/practica-git

Ejercicio 7 — Historial con buenos mensajes Buenas prácticas

Objetivo: practicar mensajes de commit claros y ver el historial crecer.

  1. Agrega una línea nueva a tu README.md describiendo el propósito de la práctica → "Changes" → Summary claro → "Commit to main".
  2. Crea un segundo archivo notas.md (VS Code) → confírmalo con otro commit distinto para ese cambio.
  3. Revisa la pestaña "History": deberías ver varios commits distintos, cada uno con su propio mensaje.
  4. Clic en "Push origin" para subir todo.
Pista
Cada commit debe representar una sola idea. Si hiciste dos cosas distintas, son dos commits, no uno — igual que si usaras comandos.

Ejercicio 8 — Reto integrador: repositorio del proyecto Integrador

Objetivo: preparar la base del repositorio del proyecto del curso (entidad sin fines de lucro), repitiendo el flujo completo.

  1. File → New Repository... con el nombre real de tu proyecto (ej. guarderia-esperanza), README inicializado y Git ignore: Java.
  2. Desde VS Code, edita el README.md: nombre del proyecto, una frase describiendo la entidad, y tu nombre como autor. Guarda.
  3. "Changes" → Summary "Estructura inicial del proyecto" → "Commit to main".
  4. Clic en "Publish repository" (público).
  5. Guarda el enlace del repositorio: lo necesitarás para la Guía 3.
¿Qué deberías ver al terminar?
Tu repositorio real en github.com/tu-usuario/guarderia-esperanza, con un commit y tu README con la descripción de la entidad. Este mismo repositorio crecerá semana a semana con el proyecto: en la Semana 7 le agregarás Spring Boot.
¿Terminaste todo?
Pasa al Challenge "Ordena el flujo Git" en nivel Difícil, o adelanta el Entregable de la Guía 3. Antes de pedir ayuda: relee el mensaje en pantalla, consulta el cheat sheet e intenta de nuevo.
