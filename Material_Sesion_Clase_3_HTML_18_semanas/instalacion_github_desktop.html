Instala GitHub Desktop: crea tu cuenta, tu app y tu primer repositorio

Guía súper detallada, pensada para quien nunca ha usado estos programas ni sabía que existían. Cero terminal, cero comandos: todo a punta de clics.
¿Esto reemplaza lo que vimos en clase?
No. En la clase y en el cheat sheet aprendiste Git por comandos (terminal): git init, git add, git commit, git push… Esta página te enseña exactamente lo mismo, pero con botones, usando el programa GitHub Desktop. Son dos caminos al mismo destino — muchos profesionales usan ambos según el momento. Si el curso te pide comandos, usa la terminal; si prefieres ver todo visualmente, usa esta guía. La tabla de equivalencias botón ↔ comando conecta ambos mundos. El Entregable de la Guía 3 acepta evidencia de cualquiera de los dos caminos.

Ruta de esta guía (en este orden)

  1. Crear tu cuenta en GitHub — 8 min
  2. Instalar Visual Studio Code — 5 min
  3. Instalar el Extension Pack for Java — 5 min
  4. Instalar GitHub Desktop — 5 min
  1. Iniciar sesión y configurar tu identidad — 5 min
  2. Crear tu primer repositorio — 5 min
  3. Tu primer cambio, commit y publicación — 5 min
  4. Verificación final, videos, troubleshooting y Plan B
Tiempo total estimado: 35–40 minutos. Si ya hiciste la instalación de la Semana 1 (VS Code + JDK + extensiones), salta directo al Paso 4.

Paso 1 — Crear tu cuenta en GitHub gratis

GitHub es el sitio de internet donde vivirá tu proyecto. Necesitas una cuenta antes de instalar cualquier otra cosa.

  1. Abre github.com/signup en tu navegador.
  2. Escribe tu correo electrónico real (usa uno que revises seguido — llegará un código de verificación) → Continuar.
  3. Crea una contraseña segura (mínimo 15 caracteres, o 8 con números y minúsculas mezclados) → Continuar.
  4. Elige un nombre de usuario. Este nombre será público y aparecerá en la URL de tus proyectos (ej. github.com/tu-usuario). Sugerencia: usa algo profesional y simple, no un apodo random — lo usarás toda tu carrera.
  5. Responde si quieres recibir noticias por correo (opcional, puedes decir que no) → Continuar.
  6. Verificación "no soy un robot": GitHub te pide resolver un pequeño acertijo visual (ej. "gira la imagen hasta que quede derecha" o similar). Sigue las instrucciones en pantalla con calma; si fallas, te deja intentar de nuevo.
  7. Clic en "Create account" (Crear cuenta).
  8. Verifica tu correo: GitHub te envía un código de 6 u 8 dígitos. Ve a tu bandeja de entrada (revisa también spam/promociones), copia el código y pégalo en la página de GitHub.
  9. GitHub puede preguntarte tu experiencia o para qué usarás la cuenta — puedes elegir "Estudiante" o simplemente saltar ese paso ("Skip personalization").
  10. Cuando veas tu panel principal (dashboard) con el logo del gato (Octocat) arriba a la izquierda, tu cuenta ya existe. 🎉
✅ Checkpoint
Si puedes ver tu panel principal en github.com con tu nombre de usuario arriba a la derecha, este paso está listo.
⚠ Guarda bien tu contraseña
Usa un gestor de contraseñas o apúntala en un lugar seguro. La necesitarás para iniciar sesión en GitHub Desktop en el Paso 5.

Paso 2 — Instalar Visual Studio Code el editor

Si ya lo instalaste en la Semana 1, salta al Paso 3. Si no, aquí el resumen (versión completa con solución de problemas en instalacion.html — Paso 2).

  1. Abre code.visualstudio.com → botón azul "Download for Windows" (o Mac).
  2. Windows: ejecuta el instalador → acepta la licencia → en "Tareas adicionales" marca todas las casillas (incluida "Agregar a PATH") → Instalar.
  3. macOS: descomprime el .zip → arrastra Visual Studio Code.app a la carpeta Aplicaciones.
  4. Abre VS Code para confirmar que instaló bien.
✅ Checkpoint
VS Code abre y ves la pantalla de bienvenida ("Welcome"). Si algo falla, la guía de la Semana 1 tiene el troubleshooting completo.

Paso 3 — Instalar el Extension Pack for Java los superpoderes

También cubierto a fondo en instalacion.html — Paso 3 (Semana 1). Resumen:

  1. En VS Code, abre Extensiones: Ctrl + Shift + X.
  2. Busca Extension Pack for Java → elige el de Microsoft → Install.
  3. Espera 1–3 minutos mientras instala 6 extensiones relacionadas.
✅ Checkpoint
Necesitas también el JDK instalado para que Java funcione de verdad (ver Paso 1 de la Semana 1) — sin él, VS Code no podrá ejecutar programas Java, aunque la extensión sí se instale.

Paso 4 — Instalar GitHub Desktop Git con botones

GitHub Desktop es una aplicación gratuita de GitHub que hace exactamente lo mismo que los comandos de Git, pero con ventanas, botones y menús — sin escribir nada en una terminal.

4.1 Descarga e instalación (Windows)

  1. Abre desktop.github.com → botón "Download for Windows".
  2. Ejecuta el archivo descargado (GitHubDesktopSetup.exe, pesa ~280 MB). No pide permisos de administrador: se instala solo para tu usuario y se abre automáticamente al terminar.
  3. Si Windows Defender/SmartScreen muestra una advertencia ("Windows protegió su PC"), clic en "Más información" → "Ejecutar de todas formas" (es normal para instaladores nuevos y de bajo volumen de descargas; GitHub Desktop es un programa oficial y seguro).

4.2 Descarga e instalación (macOS)

  1. Mismo enlace: desktop.github.com → "Download for macOS".
  2. Abre el .zip descargado, y luego el .app resultante. Si macOS dice que es de un "desarrollador no identificado": clic derecho sobre la app → Abrir → confirmar Abrir en el diálogo.
💡 ¿Y si ya tengo Git de la Semana 1?
No hay problema: GitHub Desktop trae su propia copia de Git integrada y funciona perfectamente aunque ya tengas Git instalado por línea de comandos. Puedes usar ambos caminos con el mismo repositorio, incluso alternando entre uno y otro.
⚠ ¿Y si NO tengo Git y solo voy a usar GitHub Desktop?
Perfecto, no necesitas instalarlo aparte: el Git de GitHub Desktop es suficiente para todo lo de esta guía. Ojo con un detalle: ese Git interno no queda disponible para VS Code (VS Code busca su propio "Git del sistema" para el ícono de Source Control). No es un problema — en esta guía nunca usas ese ícono, todo el add/commit/push lo haces desde la app de GitHub Desktop — pero si en algún momento VS Code te muestra "Download Git" o el ícono de Source Control aparece vacío, ignóralo (ver T9) o instala Git por línea de comandos siguiendo instalacion.html — Paso 4.

Paso 5 — Iniciar sesión y configurar tu identidad

  1. Al abrir GitHub Desktop por primera vez, verás la pantalla "Let's get started" con el botón "Sign in to GitHub.com" — haz clic ahí.
  2. Se abrirá tu navegador pidiendo autorizar la aplicación. Inicia sesión con el correo/usuario y contraseña que creaste en el Paso 1.
  3. Clic en "Authorize desktop" (Autorizar). El navegador te preguntará si quieres abrir GitHub Desktop — acepta.
  4. De vuelta en GitHub Desktop, en "Configure Git" confirma tu nombre y correo (los toma de tu cuenta automáticamente) → Continue.
  5. En la pantalla final, clic en "Finish".
✅ Checkpoint
Arriba a la derecha de GitHub Desktop debe aparecer tu nombre de usuario de GitHub. Esto es el equivalente visual a haber corrido git config --global user.name/user.email por terminal (Semana 1).
💡 Opcional: en File → Options → Integrations, confirma que el "External editor" esté configurado como Visual Studio Code (así el botón "Open in Visual Studio Code" funcionará más adelante).

Paso 6 — Crear tu primer repositorio

  1. En la pantalla principal, clic en "Create a New Repository on your Hard Drive..." (o menú File → New Repository).
  2. Completa el formulario:
    • Name: el nombre de tu proyecto, sin espacios ni tildes (ej. mi-primer-repositorio).
    • Description: una frase opcional describiendo el proyecto.
    • Local path: dónde se guardará en tu computadora (deja la ruta sugerida o elige una carpeta simple como Documentos/proyectos).
    • Marca la casilla "Initialize this repository with a README" (así ya nace con un archivo para editar).
    • Git ignore: puedes elegir "Java" en el desplegable (ignora automáticamente archivos generados por Java/Maven).
    • License: puedes dejarlo en "None" por ahora.
  3. Clic en "Create repository".
✅ Checkpoint
GitHub Desktop te muestra la pantalla principal del repositorio, con un archivo README.md en la lista y un botón "Publish repository" arriba. Esto es el equivalente visual de git init.

Paso 7 — Tu primer cambio, commit y publicación en GitHub

7.1 Edita un archivo

  1. Menú Repository → Open in Visual Studio Code (o abre la carpeta manualmente desde VS Code).
  2. Abre README.md y agrega una línea, por ejemplo: Este es mi primer proyecto versionado con GitHub Desktop.
  3. Guarda el archivo (Ctrl + S) y vuelve a GitHub Desktop.

7.2 Haz tu primer commit

  1. En GitHub Desktop, ve a la pestaña "Changes" (columna izquierda): verás README.md listado, con el cambio resaltado en la vista previa (línea agregada en verde).
  2. Confirma que la casilla junto al archivo esté marcada (así queda "preparado", como git add).
  3. Abajo a la izquierda, escribe un mensaje breve en el campo "Summary", por ejemplo: Agrega descripción al README.
  4. Clic en el botón azul "Commit to main".

7.3 Publica tu repositorio en GitHub

  1. Arriba, clic en el botón "Publish repository".
  2. En la ventana "Publish Repository", confirma el nombre y decide si será público (recomendado para este curso, así tu profesor puede verlo) o privado (desmarca "Keep this code private" si quieres que sea público).
  3. Clic en "Publish Repository".
  4. Para confirmar: menú Repository → View on GitHub — se abre tu navegador mostrando el repositorio ya en línea, con tu commit incluido.
✅ Checkpoint final
Si ves tu README.md actualizado en github.com/tu-usuario/tu-repositorio, lograste con clics exactamente lo mismo que tus compañeros lograron con git init, git add, git commit y git push.

7.4 Para cambios futuros (el ciclo se repite)

Cada vez que edites algo: guarda el archivo → GitHub Desktop lo detecta en "Changes" → escribe un mensaje → "Commit to main" → botón "Push origin" (reemplaza a "Publish repository", que solo se usa la primera vez).

Troubleshooting — si algo falla 🔧

  1. Revisa spam, promociones o "correo no deseado".
  2. Espera 2–3 minutos: a veces tarda.
  3. En la página de GitHub suele haber un enlace "Reenviar código" — úsalo antes de crear una cuenta nueva.
  4. Si usas correo institucional, algunos filtros bloquean remitentes nuevos: prueba con un correo personal (Gmail/Outlook) si el problema persiste.

Los nombres de usuario en GitHub son únicos en todo el mundo. Agrega números o variaciones (ej. ana-perez-dev) hasta encontrar uno libre. No afecta en nada tu trabajo: es solo un identificador.

  1. Cierra GitHub Desktop por completo y vuelve a abrirlo.
  2. Verifica que tu navegador predeterminado esté funcionando (ábrelo manualmente primero).
  3. Como alternativa, en la pantalla de inicio de sesión de GitHub Desktop hay un enlace pequeño "or sign in with your browser" — si ya iniciaste sesión ahí antes, prueba cerrar sesión y volver a intentar.

Ese botón solo aparece la primera vez, antes de que el repositorio tenga una versión remota. Si ya lo publicaste antes, el botón cambia a "Push origin" (o "Fetch origin" si no hay cambios nuevos que subir). Revisa también que tengas sesión iniciada (Paso 5).

En GitHub.com, entra a tu repositorio → Settings (pestaña) → baja hasta "Danger Zone" → "Change repository visibility" → elige Public. Confirma escribiendo el nombre del repositorio cuando lo pida.

Casi siempre falta escribir el mensaje en el campo "Summary" (es obligatorio). También revisa que al menos un archivo tenga la casilla marcada en la pestaña "Changes" — si no hay cambios reales, no hay nada que confirmar.

Le pasa a todos al inicio. Recuerda: GitHub (sin más) = el sitio web, github.com, donde vive tu repositorio. GitHub Desktop = la aplicación con ventanas de esta guía, la instalas en tu computadora. Git = el motor que hace el trabajo real por detrás de ambos (y de la terminal que usaste en clase). Los tres están relacionados, pero son cosas distintas.

GitHub Desktop se instala por usuario, sin pedir permisos de administrador — igual que VS Code (instalador "User"). Si aun así no puedes instalar nada, usa el Plan B de esta página (100% desde el navegador).

Es normal y no afecta tu trabajo. El Git que trae GitHub Desktop es de uso interno de esa app; no queda instalado como "Git del sistema", que es lo que busca VS Code para su panel de Source Control. En esta guía nunca necesitas ese panel: todo el add/commit/push lo haces desde la app de GitHub Desktop (Pasos 5–7), usando Repository → Open in Visual Studio Code solo para editar archivos. Si de verdad quieres que VS Code también detecte Git (por ejemplo, más adelante en el curso), instala Git por línea de comandos con instalacion.html — Paso 4 (Semana 1); ambas copias de Git conviven sin problema.

Plan B — Si no puedes instalar nada 🌐

Puedes crear tu cuenta, tu repositorio y hasta tu primer commit sin instalar absolutamente nada, directo desde github.com en cualquier navegador (incluso desde un celular):

  1. Crea tu cuenta igual que en el Paso 1 (eso siempre es 100% web).
  2. En tu perfil, clic en el botón verde "New" (o ve a github.com/new).
  3. Escribe el nombre del repositorio, marca "Add a README file" y clic en "Create repository".
  4. Dentro del repositorio, clic en el ícono de lápiz (✏️) sobre README.md para editarlo directo en el navegador.
  5. Escribe tu cambio y baja hasta "Commit changes..." → escribe un mensaje → "Commit changes".
Con esto ya cumples la evidencia mínima de la Guía 3 mientras resuelves la instalación en casa con calma. Cuando tengas VS Code, el JDK y Git (o GitHub Desktop) listos, sigue trabajando desde tu computadora con el mismo repositorio (clónalo o publícalo de nuevo desde ahí).
