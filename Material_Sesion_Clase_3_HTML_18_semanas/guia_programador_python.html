Git no es de Java: es de cualquier proyecto

A diferencia de las semanas 1 y 2, hoy no comparamos sintaxis de lenguajes: Git es el mismo Git sin importar si programas en Java, Python o cualquier otro lenguaje. Esta guía conecta lo que ya conoces (Python, y los clics de GitHub Desktop que practicaste esta semana) con el comando que hace lo mismo por debajo.
Buenas noticias si ya conoces Python
Si alguna vez ejecutaste git clone para descargar una librería o un proyecto de GitHub para tus clases de Python, ya usaste Git sin saberlo. Todo lo que aprendas hoy sirve exactamente igual para tus proyectos en Python, Java, o cualquier otro lenguaje — Git no le pertenece a ninguno.

1. Lo que SÍ cambia entre proyectos: el .gitignore

Lo único que varía de un lenguaje a otro es qué archivos generados automáticamente no quieres subir al repositorio.

🐍 .gitignore típico de Python☕ .gitignore típico de Java
 
__pycache__/
*.pyc
venv/
.env
.pytest_cache/
 
target/
*.class
.idea/
*.iml
.env
Ambos ignoran lo mismo en esencia: entornos virtuales/dependencias (venv/ ↔ nada equivalente hoy, pero será target/ con Maven desde la Semana 7), archivos compilados (*.pyc ↔ *.class) y configuración del editor (.idea/). El comando para usarlo es idéntico en ambos mundos: crear un archivo .gitignore y listar los patrones.

2. Lo que ya sabes hacer con GitHub Desktop: traducción a comandos

Esta semana aprendiste primero el "clic" (GitHub Desktop). Aquí ves qué comando hace exactamente lo mismo por debajo.

Acción en la interfaz gráficaComando equivalente en terminal
Botón "+" junto a un archivo cambiado (stage)git add archivo
Caja de texto "Commit message" + botón "Commit"git commit -m "mensaje"
Botón "Sync" / "Push origin"git push
Botón "Fetch origin" / "Pull"git pull
Menú "Current Branch" → "New Branch"git checkout -b nombre-rama
Ícono de "historial" / "History"git log --oneline
Ninguna es "mejor": los equipos profesionales usan ambas según el momento. Conocer también el comando te sirve para trabajar en cualquier servidor sin interfaz gráfica (donde se despliegan la mayoría de aplicaciones reales) y es el estándar que asume cualquier tutorial o compañero de trabajo.

3. Ejercicios de traducción: de la acción a el comando

Traducción 1 — "Guardé mi trabajo con Ctrl+S y quiero respaldarlo"

Tienes un archivo nuevo, datos.py (o Main.java), y quieres que Git lo empiece a vigilar y guarde una fotografía.

Solución 
git add datos.py
git commit -m "Agrega archivo de datos inicial"

Traducción 2 — "Quiero que mi compañero vea mis cambios"

Ya hiciste commit localmente. ¿Qué falta para que exista en GitHub?

Solución 
git push
(La primera vez en un repositorio nuevo: git push -u origin main.)

Traducción 3 — "No quiero subir mi carpeta de dependencias"

Tienes una carpeta venv/ (Python) que no debe subirse jamás al repositorio.

Solución 
# dentro de .gitignore
venv/
El mismo principio se usará con target/ cuando trabajes con Maven en Java (Semana 7).

Traducción 4 — Reto inverso: ¿qué pasó aquí?

Un compañero ejecutó estos 3 comandos seguidos. Describe en una frase qué logró:

git add .
git commit -m "Estructura inicial"
git push -u origin main
Solución
Preparó todos sus archivos, guardó una fotografía local con mensaje descriptivo, y la subió a GitHub por primera vez (conectando su rama local main con la remota).
