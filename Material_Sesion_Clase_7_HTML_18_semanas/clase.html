Semana 7 — Entorno de desarrollo y Spring Boot

Sábado 22 de agosto de 2026 · 11:10–12:20 · En línea · Primera semana con código Java real ejecutándose de verdad. Límite de alcance: hoy NO se escriben controladores ni endpoints propios (@RestController llega en la Semana 8) — solo se genera, se explora y se ejecuta el proyecto base.

Objetivos (hoy)

  • Confirmar que JDK 21 y VS Code (Semana 1) siguen funcionando, y agregar la extensión de Spring Boot.
  • Explicar qué hace Maven/Gradle y por qué Spring Initializr ya incluye el wrapper (no hay que instalar Maven aparte).
  • Generar un proyecto real en start.spring.io y recorrer su estructura.
  • Ejecutar el proyecto y leer el log de arranque hasta encontrar la línea de éxito.
  • Modificar application.properties (puerto, nombre) y confirmar el cambio.

Elevator pitch (1 minuto): Spring Boot es un framework — un conjunto de piezas ya construidas (servidor web incluido, configuración lista) para no escribir desde cero todo lo que MVC y arquitectura en capas (Semanas 5–6) necesitan. En vez de programar un servidor, lo declaras con anotaciones y Spring lo construye por ti.

El atajo que ahorra una instalación completa
No vamos a instalar Maven por separado. Spring Initializr genera un archivo mvnw (Maven Wrapper) dentro del proyecto — es una copia de Maven ya lista para ese proyecto. Menos pasos, menos riesgo de errores de instalación.

A propósito NO agregamos Thymeleaf ni Spring Data JPA hoy. Cada dependencia se introduce cuando toca su tema (Thymeleaf en la Semana 10, JPA en la Semana 12) — así cada semana entiende exactamente qué agregó y por qué.

Pulsa Generate, descarga el .zip, y descomprímelo en una carpeta fácil de encontrar (ej. Documentos/proyectos-java).

Abre la carpeta descomprimida con VS Code → File → Open Folder y recorre, en vivo, estos elementos:

demo-spring-boot/
├── mvnw, mvnw.cmd        ← el "Maven Wrapper" (no instalamos Maven aparte)
├── pom.xml               ← la "receta" del proyecto: dependencias y versión de Java
└── src/
    ├── main/java/.../DemoSpringBootApplication.java   ← el punto de partida
    └── main/resources/application.properties          ← configuración del proyecto
ArchivoQué hace
pom.xmlLista las dependencias (ej. Spring Web) y le dice a Maven qué descargar y cómo empaquetar.
...Application.javaTiene el método main y la anotación @SpringBootApplication — es el botón de encendido de todo el proyecto.
application.propertiesConfiguración en pares clave=valor (ej. el puerto del servidor). Hoy está casi vacío; lo iremos llenando semana a semana.
Curiosidad técnica (valor de la semana)
@SpringBootApplication en realidad combina 3 anotaciones en una (auto-configuración, escaneo de componentes y punto de entrada) — Spring Boot automatiza configuración que en frameworks más antiguos había que escribir a mano.

  • Estirar manos y espalda, agua, mirar lejos de la pantalla 20 segundos.
  • Micro-check en el chat: "en una palabra, ¿qué archivo tiene el método main?"

Arrancar el proyecto (cualquiera de las dos formas, mostrar ambas):

  • Abre ...Application.java y pulsa el botón ▶ Run que aparece sobre main (extensión de Java).
  • O, en la terminal integrada: ./mvnw spring-boot:run (Mac/Linux) o mvnw spring-boot:run (Windows).
...
Tomcat started on port 8080 (http) with context path ''
Started DemoSpringBootApplication in 2.145 seconds (process running for 2.4)
✅ Señal de éxito
La línea Started ... Application in X seconds significa que tu servidor Tomcat (incluido dentro de Spring Boot) ya está corriendo. No necesitas instalar Tomcat aparte — viene "embebido".

Abre el navegador en http://localhost:8080. Aparece una Whitelabel Error Page (código 404).

Esto NO es un error de configuración — es lo esperado
El servidor sí está corriendo (por eso responde algo), pero todavía no le dijimos qué mostrar en la ruta / — eso se llama definir una "ruta" o "endpoint", y es exactamente el tema de la Semana 8. Hoy, ver esta página confirma que todo funciona.

Detén el proyecto (botón ⏹ o Ctrl+C en la terminal) y abre application.properties. Agrega:

server.port=8081
spring.application.name=demo-spring-boot

Vuelve a ejecutar y confirma en el log que ahora dice port 8081 — visita http://localhost:8081 y verifica que también responde. Metodología estructurada (valor de la semana): una configuración inicial ordenada (puerto, nombre) evita confusiones cuando el proyecto crezca.
