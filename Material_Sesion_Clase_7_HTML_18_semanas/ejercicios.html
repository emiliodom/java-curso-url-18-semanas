Guía de ejercicios · Semana 7 · 100% en tu propia computadora

Nada de simuladores hoy: Java real, corriendo de verdad

Estos 7 ejercicios NO se resuelven en esta página — se hacen en tu terminal, VS Code y navegador, con un proyecto de práctica desechable llamado laboratorio-spring. Cada uno tiene una pista, un checkpoint y una solución en <details> por si te atoras.
Antes de empezar: la pregunta ancla de esta semana
En cada ejercicio pregúntate: ¿mi terminal dice "Started ... Application in X seconds"? Si sí, tu proyecto está corriendo correctamente — sin importar qué muestre el navegador todavía.

Ejercicio 1 — Verifica tu JDK Calentamiento

Abre una terminal y ejecuta:

java -version
javac -version

Tu turno: ¿qué número de versión aparece? ¿Coincide con lo que instalaste en la Semana 1?

Solución
Debe aparecer 21 (o 17/25) en ambos comandos. Si en cambio ves "no se reconoce como un comando", resuelve el troubleshooting del cheat sheet antes de continuar — todo lo demás depende de esto.

Ejercicio 2 — Genera tu proyecto de práctica Real

En start.spring.io, genera un proyecto con: Maven, Java, versión estable más reciente, Group gt.edu.url, Artifact laboratorio-spring, Packaging Jar, Java 21, dependencia Spring Web únicamente. Descarga y descomprime el .zip.

Tu turno: antes de abrirlo, predice: ¿cuántas carpetas main vas a encontrar dentro de src?

Solución
Una carpeta main (tu código) y otra test (pruebas automáticas, no la usaremos todavía). Dentro de main hay java (tu código) y resources (configuración).

Ejercicio 3 — Explora la estructura Real

Abre la carpeta en VS Code (File → Open Folder) y localiza: pom.xml, LaboratorioSpringApplication.java y application.properties.

Tu turno: antes de leer la solución, escribe en una palabra qué crees que hace cada uno de los 3 archivos.

Solución
pom.xml: dependencias/versión. LaboratorioSpringApplication.java: enciende el proyecto (tiene main y @SpringBootApplication). application.properties: configuración.

Ejercicio 4 — Ejecuta el proyecto por primera vez Real

Abre LaboratorioSpringApplication.java y pulsa ▶ Run sobre main (o usa mvnw spring-boot:run en la terminal).

Tu turno: busca en el log la línea que empieza con Started. ¿Cuántos segundos tardó en arrancar y en qué puerto quedó escuchando?

Solución
Algo como Started LaboratorioSpringApplication in 2.1 seconds, y unas líneas arriba Tomcat started on port 8080. El número exacto de segundos varía en cada computadora — no es un error si es distinto al del profesor.

Ejercicio 5 — Visita localhost:8080 Interpretar

Con el proyecto todavía corriendo, abre http://localhost:8080 en tu navegador.

Tu turno: aparece una página de error "Whitelabel Error Page" con código 404. ¿Es un fracaso? Justifica con lo que viste en el log.

Solución
No es un fracaso: el log ya mostró Started ... Application, así que el servidor SÍ está corriendo. El 404 solo dice "no hay ninguna ruta configurada para /" — definir rutas es el tema de la Semana 8.

Ejercicio 6 — Cambia el puerto Configuración

Detén el proyecto (⏹ o Ctrl+C). En application.properties agrega server.port=8081. Vuelve a ejecutar.

Tu turno: ¿qué pasa si visitas localhost:8080 ahora (con el proyecto ya corriendo en 8081)?

Solución
El navegador no puede conectarse (error de conexión, no Whitelabel) — ya no hay nada escuchando en el puerto 8080. El log confirma el nuevo puerto: Tomcat started on port 8081.

Ejercicio 7 — Reto integrador: provoca y resuelve un error real Integrador

Con el proyecto corriendo en una terminal, abre una segunda terminal en la misma carpeta y ejecuta mvnw spring-boot:run otra vez, sin cambiar el puerto.

Tu turno: ¿qué mensaje de error aparece, y cuáles son las 2 formas de resolverlo?

Ejemplo de solución
Aparece Web server failed to start. Port 8081 was already in use. Se resuelve deteniendo la primera copia (Ctrl+C en su terminal) o cambiando server.port a otro número antes de ejecutar la segunda copia. Este es el mismo error que vas a ver en el escenario "con error" del Challenge.
