Proyecto · Entregable de la Guía de Aprendizaje 7 (1 pt)

Tu proyecto Spring Boot real, corriendo y en GitHub

Esta página tiene dos partes: primero una guía paso a paso para generar el proyecto Spring Boot de tu proyecto real, y al final la plantilla calificable que debes completar y entregar. Fecha límite: antes de la Sesión 8 (29 de agosto de 2026). Esta semana no tiene Entrega Parcial adicional — el siguiente hito es en la Semana 9.
Antes de empezar
Necesitas: tu Ficha del Proyecto (nombre de la entidad/institución) a la mano, tu repositorio real de GitHub (Semanas 3–4, con su rama development), y tu JDK 21 verificado. Este proyecto Spring Boot será la base que crecerá hasta la Entrega Parcial 2 (Semana 9).

Parte guiada — genera y ejecuta tu proyecto real

Paso 1 — Elige Group y Artifact con datos reales de tu proyecto

Usa el nombre de tu entidad/institución (de tu Ficha del Proyecto) para definir:

Group:    gt.edu.url  (o similar, en minúsculas, sin acentos ni espacios)
Artifact: nombre-de-tu-proyecto-en-minusculas-con-guiones
          (ej. "guarderia-esperanza", "dispensario-santa-rita")
✅ Checkpoint: tienes decidido tu Group y tu Artifact, coherentes con el nombre real de tu proyecto.

Paso 2 — Genera el proyecto en Spring Initializr

En start.spring.io: Project Maven, Language Java, Spring Boot la versión más alta que no diga SNAPSHOT, tu Group y Artifact del Paso 1, Packaging Jar, Java 21, dependencia Spring Web únicamente. Genera y descomprime el .zip.

✅ Checkpoint: tienes una carpeta con pom.xml, tu clase Application.java y application.properties.

Paso 3 — Ábrelo en VS Code y ejecútalo por primera vez

File → Open Folder sobre la carpeta descomprimida. Abre la clase Application.java y pulsa ▶ Run sobre main (o usa mvnw spring-boot:run en la terminal).

✅ Checkpoint: en la terminal aparece "Started ... Application in X seconds", y al visitar http://localhost:8080 ves la Whitelabel Error Page (señal de éxito, no de fracaso — todavía no hay rutas).

Paso 4 — Personaliza application.properties

Detén el proyecto y agrega, con el nombre real de tu proyecto:

spring.application.name=guarderia-esperanza

Vuelve a ejecutar y confirma que sigue arrancando sin errores.

✅ Checkpoint: application.properties tiene el nombre real de tu proyecto y el proyecto arranca sin problema.

Paso 5 — Sube el proyecto a tu repositorio real

En GitHub Desktop, dentro de tu repositorio de las Semanas 3–4: cambia a la rama development, copia (o mueve) toda la carpeta del proyecto generado dentro de tu repositorio local, confirma el cambio ("Commit to development") con el resumen "Agrega el proyecto Spring Boot inicial", y publica/sincroniza la rama.

✅ Checkpoint: tu rama development en GitHub.com muestra la carpeta completa del proyecto Spring Boot (incluyendo pom.xml y src/).
Solución de problemas frecuentes
SituaciónQué hacer
No sé qué Group usarCualquier valor coherente y en minúsculas sirve (ej. gt.edu.url); lo importante es que no cambie entre sesiones futuras.
"Port 8080 was already in use" al ejecutarYa tienes otra copia corriendo (quizás del Ejercicio 2). Deténla o usa otro puerto temporalmente con server.port.
GitHub Desktop no detecta los archivos nuevosVerifica que copiaste la carpeta DENTRO de la carpeta de tu repositorio local (no en otro lugar).
No tengo permisos/tiempo para instalar en esta computadoraUsa el Plan B de la Semana 1 mientras resuelves tu entorno real — recuerda que Spring Boot exige JDK local para el resto del curso.
