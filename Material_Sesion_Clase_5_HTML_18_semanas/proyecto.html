★ Entrega Parcial 1 (5 pts) · Semana 5 · Aplica MVC a tu proyecto real

Propuesta con estructura MVC de tu proyecto

Aquí aplicas, sobre tu repositorio real, exactamente el mismo razonamiento que practicaste en Ejercicios y el Challenge: identificar Modelo, Vista y Controlador — pero ahora de tu propia aplicación.
Esta es la entrega más grande hasta ahora — tómate tu tiempo
Vale 5 puntos como "Avance del Proyecto — Entrega Parcial 1", además del punto normal de la Guía 5. No es una implementación en código todavía (eso empieza en la Semana 7) — es una propuesta bien pensada: qué entidades tendrá tu Modelo, qué pantallas tendrá tu Vista, y qué acciones coordinará tu Controlador.

Paso 1 — Recuerda qué construyes

Tu proyecto: una app para el registro y gestión de una entidad sin fines de lucro (guardería, casa hogar o dispensario comunitario), con registro de beneficiarios, operaciones CRUD, autenticación por roles y una interfaz responsiva. Antes de seguir, ten a la mano tu README.md de la Semana 4 — ahí ya describiste tu entidad y sus funcionalidades planeadas.

✅ Checkpoint: tienes claro qué entidad atiende tu proyecto y qué funcionalidades planeaste.

Paso 2 — Identifica tu Modelo (datos y reglas)

Lista 2 o 3 "entidades" reales de tu proyecto (lo que se guardará como datos) y una regla de negocio para cada una. Ejemplo, si tu entidad es una guardería:

MODELO
- Beneficiario: nombre, fecha de nacimiento, nombre del encargado
  regla: "la fecha de nacimiento no puede ser futura"
- Encargado: nombre, teléfono, parentesco
  regla: "el teléfono debe tener 8 dígitos"
✅ Checkpoint: tienes al menos 2 entidades con sus atributos y al menos 1 regla de negocio cada una.

Paso 3 — Identifica tu Vista (pantallas)

Lista las pantallas principales que un usuario vería. No necesitas diseñarlas hoy — solo nombrarlas y decir qué muestran.

VISTA
- Formulario de registro de beneficiario
- Listado de beneficiarios registrados
- Pantalla de inicio de sesión
✅ Checkpoint: tienes al menos 3 pantallas identificadas, coherentes con tus Modelos del Paso 2.

Paso 4 — Identifica tu Controlador (acciones)

Por cada acción importante del usuario, describe qué coordina el Controlador (recibe → le pregunta al Modelo → decide qué Vista mostrar).

CONTROLADOR
- Registrar beneficiario: recibe el formulario, le pide al Modelo
  validar y guardar, muestra el listado actualizado o el error.
- Iniciar sesión: recibe usuario/contraseña, le pregunta al Modelo
  si son válidos, muestra el panel principal o un error.
✅ Checkpoint: cada Controlador menciona qué recibe, a qué Modelo le pregunta, y qué Vista muestra según el resultado.

Paso 5 — Arma tu diagrama MVC

Con los pasos 2 a 4 ya tienes todo el contenido — ahora solo hay que presentarlo como diagrama. Dos opciones válidas, elige la que prefieras:

  • Opción simple (sin herramientas nuevas): un archivo de texto ARQUITECTURA.md con las 3 secciones de arriba (Modelo/Vista/Controlador) y flechas de texto mostrando el flujo, ej. Vista → Controlador → Modelo → Controlador → Vista.
  • Opción visual: un diagrama de cajas y flechas hecho en draw.io o Google Drawings, exportado como imagen y agregado a tu repositorio.
No hace falta que sea perfecto
Lo que se evalúa es que las 3 capas estén bien identificadas y sean coherentes entre sí (que la Vista del Paso 3 tenga sentido con el Controlador del Paso 4, y ese con el Modelo del Paso 2) — no el nivel de diseño gráfico.

Paso 6 — Reorganiza las carpetas de tu repositorio

Usando lo aprendido en la Semana 4: crea una rama nueva para este cambio.

  1. GitHub Desktop → "Current Branch" → "New Branch" → nombre estructura-mvc.
  2. Dentro de tu proyecto, crea 3 carpetas: modelo/, vista/, controlador/ (para el código que llegará en la Semana 7 — hoy solo son carpetas marcador de posición).
  3. Dentro de cada carpeta, agrega un README.md corto explicando qué irá ahí (puedes usar el contenido de los pasos 2, 3 y 4).
  4. Agrega también tu ARQUITECTURA.md o la imagen de tu diagrama en la raíz del proyecto.
  5. "Changes" → Summary: "Agrega propuesta de estructura MVC" → "Commit to estructura-mvc".
✅ Checkpoint: tu rama tiene las 3 carpetas, cada una con su README, más el diagrama general.

Paso 7 — Publica tu Pull Request

  1. Clic en "Publish branch".
  2. Menú Branch → Create Pull Request. Verifica: base: main ← compare: estructura-mvc.
  3. Título: "Propuesta de arquitectura MVC — Entrega Parcial 1". En la descripción, pega o enlaza tu diagrama.
  4. Clic en "Create pull request". Copia el enlace — lo necesitarás en el Entregable.
✅ Checkpoint: tienes una Pull Request abierta con tu diagrama visible en la descripción o en los archivos.

Paso 8 — Fusiona y sincroniza

  1. (Si trabajas con un compañero) Pide una revisión rápida: ¿las 3 capas son coherentes entre sí?
  2. "Merge pull request" → "Confirm merge" en github.com.
  3. En GitHub Desktop: "Current Branch" → main → clic en "Fetch origin".
✅ Checkpoint: tu repositorio en main ya muestra las carpetas modelo/, vista/, controlador/ y tu diagrama.
Solución de problemas frecuentes
SituaciónQué hacer
No sé cuántas entidades debe tener mi ModeloEmpieza con 2: la entidad principal (ej. Beneficiario) y una relacionada (ej. Encargado/Donación). Puedes agregar más semanas después.
Mi Vista y mi Controlador no coincidenRevisa que cada pantalla del Paso 3 tenga al menos una acción correspondiente en el Paso 4 — si una pantalla no tiene ninguna acción, probablemente falta un Controlador.
Git no me deja crear una carpeta vacíaGit no rastrea carpetas vacías — por eso cada carpeta debe tener su archivo README.md adentro, así ya no está vacía.
No sé usar draw.ioUsa la "opción simple" del Paso 5: un archivo de texto ARQUITECTURA.md es igual de válido.
Plan B (si algo falla técnicamente)
Si GitHub Desktop no coopera: crea las carpetas y archivos directo en la interfaz web de GitHub (botón "Add file" → "Create new file", escribiendo modelo/README.md como nombre para crear la carpeta automáticamente), luego abre la Pull Request desde ahí — el resultado final es el mismo.
