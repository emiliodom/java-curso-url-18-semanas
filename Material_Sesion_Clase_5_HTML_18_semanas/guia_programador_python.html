El mismo patrón, un nombre distinto (y confuso)

MVC existe en Python igual que en Java — pero el framework más popular de Python para web, Django, le cambia el nombre a dos de las tres capas. Si algún día lees un tutorial de Django, esta página te evita una confusión muy común.
Buenas noticias si ya conoces Python
Si alguna vez viste un proyecto de Django con archivos llamados models.py, views.py y una carpeta templates/, ya viste MVC en acción — solo que con otro nombre. La idea de separar datos, presentación y coordinación es exactamente la misma.

La trampa de nombres más famosa entre frameworks
El archivo views.py de Django sí hace el trabajo de un Controlador (recibe la petición, decide qué hacer) — pero Django decidió llamarlo "View" por razones históricas. No es un error tuyo si te confunde: hasta desarrolladores con experiencia lo mencionan la primera vez que cambian de framework.

2. Lo que NO cambia entre frameworks (o lenguajes)

  • La separación de responsabilidades es la misma: datos/reglas por un lado, presentación por otro, coordinación en medio.
  • Los antipatrones también son universales: un views.py de Django que valida reglas de negocio él mismo es un "controlador gordo", igual que en Java.
  • Flask (otro framework de Python, más pequeño que Django) no exige una estructura fija, pero la mayoría de sus proyectos organizan sus archivos con el mismo espíritu: models.py, routes.py (equivalente al Controlador) y una carpeta templates/.

3. Ejercicios de traducción: de Django a MVC

Traducción 1 — App de lista de tareas (to-do)

En Django, dentro de views.py hay una función que recibe la petición cuando marcas una tarea como completada, y decide qué página mostrar después. En términos de MVC (Java), ¿qué capa es esa función?

Solución
Es un Controlador, aunque el archivo se llame "views.py". Recibe una acción y decide el flujo — exactamente el trabajo del mesero.

Traducción 2 — Reproductor de música (playlist)

En Django, models.py define una clase Cancion con un atributo duracion y la regla "la duración no puede ser 0 o negativa". ¿A qué capa de MVC equivale?

Solución
Es el Modelo: datos + regla de negocio, sin importar el framework.

Traducción 3 — Agenda de turnos de una clínica dental

Un archivo agenda.html dentro de templates/ muestra la lista de citas del día. ¿A qué capa de MVC equivale?

Solución
Es la Vista: presenta información, sin decidir ni calcular nada.

Traducción 4 — Reto inverso: de Java a Django

Tienes, en Java/Spring: un Controlador que recibe un formulario, un Modelo Usuario que valida el correo, y una Vista que muestra "Registro exitoso". Si migraras esto a Django, ¿en qué archivo/carpeta pondrías cada parte?

Solución
El Controlador → una función en views.py. El Modelo Usuario → una clase en models.py. La Vista de "Registro exitoso" → un archivo .html dentro de templates/.
